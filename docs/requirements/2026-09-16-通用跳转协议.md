# App 通用跳转协议

## 基本信息

- 日期：2026-09-16
- 当前状态：通用跳转处理器、`test_flow`映射、Push 点击与 iOS Universal Link 已接入；Android App Links 待开发
- 适用入口：Push 通知点击、Universal Link
- 实现基准：不同外部入口统一转换为`target + action`，由客户端白名单映射到 GoRouter 路由
- 调用方向：Push / Universal Link → CommonJumpHandler → GoRouter → 目标页面

## 目标

为 Push 和 Universal Link 定义统一的 App 页面跳转协议：

1. 外部入口统一传递`target`和`action`。
2. Push 和 Universal Link 只负责提取字段，不分别维护页面跳转逻辑。
3. 客户端通过白名单校验`target`，禁止外部数据直接执行 Flutter 路由。
4. 页面映射、参数解析和跳转执行集中维护，便于后续扩展新的目标页面。

Push 到达设备时不自动跳转，仅在用户点击通知后处理；Universal Link 同样由用户点击后进入通用跳转流程。

## 流程顺序

```text
Push 通知点击
  ├─ App 在后台 → FirebaseMessaging.onMessageOpenedApp
  └─ App 已终止 → FirebaseMessaging.getInitialMessage
                         ↓
                  提取 target、action
                         ↓
Universal Link 点击 → 提取 target、action
                         ↓
                 CommonJumpHandler
  ├─ 用户未登录 → 不执行跳转并记录日志
  ├─ target 不在白名单 → 不执行跳转并记录日志
  ├─ 需要 action 的 target 参数无效 → 不执行跳转并记录日志
  ├─ 已在目标页面 → 不重复跳转并记录日志
  └─ 校验通过 → 映射到 GoRouter 路由 → 打开目标页面
```

## 1. 跳转字段

| 字段 | 类型 | 必须 | 说明 |
| --- | --- | --- | --- |
| `target` | string | 是 | 页面稳定标识，由客户端维护白名单映射，不直接使用 Flutter 路由地址 |
| `action` | string | 否 | 页面所需参数，使用 URL Query String 格式；没有参数时可省略，客户端按空字符串处理 |

### 1.1 target

`target`用于标识需要打开的 App 页面，例如：

```text
target=test_flow
```

- 服务端和外部链接只能使用本文已登记的`target`。
- 客户端不得将`target`作为 GoRouter 路由地址直接执行。
- 已发布的`target`必须保持语义稳定，避免历史 Push 或链接跳转到错误页面。

### 1.2 action

`action`保存目标页面需要的参数：

| 参数数量 | 示例 |
| --- | --- |
| 无参数 | `action=""` |
| 一个参数 | `action="drama_id=10"` |
| 多个参数 | `action="drama_id=10&uid=100"` |

参数规则：

1. 目标页面不需要参数时，可省略`action`，客户端按空字符串处理。
2. 多个参数使用`&`连接。
3. 参数名和值按照 URL Query String 规则编码和解码。
4. 每个`target`单独定义是否需要使用`action`。
5. 不需要`action`的`target`完全忽略该字段；字段缺失、空字符串或任意非空内容均不影响跳转。
6. 需要`action`的`target`才执行参数格式与业务校验。

## 2. Push 跳转

Push 的跳转信息放在 FCM Data Payload 中，字段值均为字符串：

```json
{
  "message": {
    "token": "FCM_TOKEN",
    "notification": {
      "title": "检测提醒",
      "body": "开始一次新的检测"
    },
    "data": {
      "target": "test_flow",
      "action": ""
    }
  }
}
```

- 通知标题使用`notification.title`。
- 通知正文使用`notification.body`。
- 页面跳转字段使用`data.target`和`data.action`。
- 客户端收到 Push 时不直接跳转。
- 用户从后台点击通知时，通过`FirebaseMessaging.onMessageOpenedApp`处理。
- 用户从终止状态点击通知时，通过`FirebaseMessaging.getInitialMessage`处理。
- 两种点击入口都将`target`和`action`交给`CommonJumpHandler`。

## 3. Universal Link 跳转

Universal Link 使用`target`和`action`作为查询参数：

```text
https://<universal-link-domain>/<path>?target=test_flow&action=
```

当目标页面的`action`为空字符串时，也可直接省略该字段：

```text
https://<universal-link-domain>/<path>?target=test_flow
```

当`action`内部包含`=`、`&`或其他 URL 保留字符时，必须先对整个`action`值进行 URL 编码，避免内部参数被识别为 Universal Link 的外层参数。

逻辑参数：

```text
target=test_flow
action=drama_id=10&uid=100
```

对应链接：

```text
https://<universal-link-domain>/<path>?target=test_flow&action=drama_id%3D10%26uid%3D100
```

Universal Link 当前支持`api-test.naloresults.com`与`api.naloresults.com`，AASA 允许所有路径。入口路径不属于`target`页面映射的一部分。

## 4. 客户端架构

通用跳转能力集中维护在以下文件：

```text
lib/app/navigation/common_jump_handler.dart
  维护 target 白名单
  解析 action 参数
  校验目标页面参数
  映射并执行 GoRouter 跳转

lib/app/router/app_router.dart
  声明 App 内部路由

lib/app/navigation/universal_link_provider.dart
  监听 iOS Universal Link
  校验 HTTPS 协议与域名白名单
  提取 target 和 action 并交给 CommonJumpHandler

lib/app/navigation/initial_page_ready_provider.dart
  接收冷启动分流后首个业务页面的首帧就绪信号
  不包含 Universal Link 解析或页面跳转逻辑

lib/features/notifications/providers/push_messaging_provider.dart
  监听 Push 前台消息、后台点击和终止状态初始消息
  提取 data.target 和 data.action 并交给 CommonJumpHandler
  冷启动点击时等待首个业务页面就绪且登录态恢复后再执行跳转
```

`CommonJumpHandler`对外提供统一调用入口：

```dart
ref.read(commonJumpHandlerProvider).navigate(
  target: target,
  action: action,
);
```

返回规则：

- 成功识别并发起跳转时返回`true`。
- `target`未知、需要`action`的 target 参数不符合页面要求，或已在目标页面时返回`false`。
- 用户未登录时返回`false`，不执行任何外部页面跳转。
- 跳转失败原因使用项目 Logger 记录，不输出敏感参数。

Push 和 Universal Link 的监听代码不得重复维护页面映射，也不得绕过`CommonJumpHandler`直接执行外部指定的路由。

## 5. 页面映射

| target | 页面 | Flutter 路由 | action | 当前状态 |
| --- | --- | --- | --- | --- |
| `test_flow` | 检测流程页 | `TestFlowPage.path`（`/test`） | 不使用，完全忽略 | 已实现 |
| `tab_home` | 首页 Tab | `HomePage.path`（`/home`） | 不使用，完全忽略 | 已实现 |
| `tab_shop` | Shop Tab | `HomePage.shopPath`（`/home?tab=shop`） | 不使用，完全忽略 | 已实现 |

新增外部跳转页面时必须同时：

1. 在本表登记`target`、目标页面和参数要求。
2. 在`common_jump_handler.dart`中增加白名单映射和参数校验。
3. 保持已经发布的`target`语义不变。

## 6. 实施顺序

1. 定义`target + action`通用跳转协议。
2. 实现`CommonJumpHandler`以及`test_flow`白名单映射。
3. 将 Push 后台点击和终止状态点击接入`CommonJumpHandler`。
4. 配置 Universal Link 域名、系统能力和关联文件。
5. 将 Universal Link 解析结果接入`CommonJumpHandler`。
6. 后续按业务需要补充新的页面映射和参数校验。

## 7. 完成标准

- Push 和 Universal Link 使用统一的`target + action`协议。
- Push 仅在用户点击通知后执行页面跳转。
- 两种外部入口都通过`CommonJumpHandler`处理，不重复维护页面映射。
- `test_flow`可以正确映射到`TestFlowPage.path`，不使用`action`。
- `tab_home`和`tab_shop`分别切换到主容器的首页 Tab 与 Shop Tab，不使用`action`。
- 用户已在检测流程页时，再次收到`test_flow`不会重复压入页面。
- 检测流程的中间环节是同一路由内的状态切换；通过`RouteObserver + RouteAware`判断检测流程页是否位于顶层，不依赖手动的`initState/dispose`标记或可能滞后的 URI。
- Universal Link 到达时若已明确未登录，直接丢弃，后续登录后不补跳转。
- App 冷启动时 Universal Link 只保存待处理意图，不监听路由或主动导航；AuthGate 依原流程分流，首个业务页面完成首帧后再消费该意图。
- 首个业务页面为未登录页时，意图会由统一跳转处理器按登录规则丢弃，后续登录不补跳转。
- 未知`target`，以及需要`action`的 target 所携带的无效参数，不会触发跳转。
- 外部输入不能直接执行任意 Flutter 路由。
- 新增页面映射时，同步更新本文的页面映射表和客户端白名单。
