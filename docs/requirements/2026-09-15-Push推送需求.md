# Firebase Push 接入需求

## 基本信息

- 日期：2026-09-15
- 当前状态：iOS 基础配置及 Dart 接入代码已写入，待依赖安装与服务端联调
- 适用平台：iOS、Android
- 推送平台：Firebase Cloud Messaging（FCM）
- iOS 通道：FCM → Apple Push Notification service（APNs）
- 架构：Flutter + Riverpod + MVVM，调用方向为 Provider/ViewModel → Repository → Service

## 目标

为 App 接入 Firebase Push，完成通知权限处理、FCM Token 获取与上送、Token 刷新、远程消息接收和通知点击处理。

所有 Push 均由 Nalo 服务端通过 FCM 下发。客户端不计算业务触发条件、不调度 Push，也不创建本地通知替代服务端 Push。

## 流程顺序

```text
App 获取系统通知权限
  → Firebase Messaging 获取 FCM Token
  → 用户登录成功
  → POST /api/v1/app/push-tokens 上送 Token
  → 登录状态有效期间监听 FCM Token 刷新并重新上送

用户退出登录 / 登录过期 / 注销账号 / UID 改变
  → 服务端处理 Token 与 UID 的清理或重新绑定
  → 客户端不删除 FCM Token、不调用解绑接口

Nalo 服务端调用 FCM 下发 Push
  → App 接收远程消息
  ├─ 前台：交给客户端前台消息处理
  ├─ 后台：系统展示通知
  └─ 终止状态：系统展示通知
  → 用户点击通知
  → App 根据消息数据执行页面跳转
```

## 1. 职责边界

### 1.1 客户端职责

1. 请求并读取系统通知权限。
2. 获取 FCM Token。
3. 登录成功后将 FCM Token 上送至 Nalo 服务端。
4. 登录状态有效期间监听 FCM Token 刷新并重新上送。
5. 接收前台远程消息。
6. 处理从后台或终止状态点击通知后的 App 跳转。
7. Token 上送或消息处理失败时使用项目 Logger 记录，不阻断 App 核心流程。

### 1.2 服务端职责

1. 保存用户、平台与 FCM Token 的关联。
2. 决定 Push 的接收用户、业务内容、触发时机和发送频率。
3. 通过 FCM 下发全部 Push。
4. 处理 FCM 返回的无效 Token。
5. 在退出登录、登录过期、注销账号或 UID 改变时，处理 Token 与 UID 的清理或重新绑定。

客户端不实现服务端业务 Push 规则。

## 2. Firebase Messaging

- Flutter 使用`firebase_messaging`接入 FCM。
- Firebase 初始化继续复用项目现有`firebase_core`配置。
- iOS 和 Android 分别使用对应 Firebase App 的配置文件。
- FCM Token 仅用于 Push 寻址，不等同于项目 Device ID。
- 客户端不保存 APNs`.p8`或 Firebase 服务端凭证。

## 3. 通知权限

- iOS 在系统允许的时机请求通知权限。
- Android 13 及以上请求系统通知权限。
- 用户拒绝通知权限时，不影响登录、首页和检测流程。
- App 从系统设置返回前台后，重新读取通知权限状态。
- 客户端现有通知权限入口继续作为统一权限入口。

## 4. FCM Token

### 4.1 获取时机

- 用户登录成功后获取当前 FCM Token 并准备上送。
- iOS 冷启动恢复登录态时读取一次当前 FCM Token，取得有效 Token 时上送；未取得时本次不调用接口。
- FCM Token 为空时不调用上送接口。

### 4.2 刷新

- 监听 Firebase Messaging 的 Token 刷新事件。
- 登录状态有效时，收到新 Token 后重新调用 Token 上送接口。
- 未登录时不调用 Token 上送接口，下一次登录成功后上送当时的有效 Token。
- 不假设 FCM Token 永久不变。

### 4.3 用户身份变化

- 退出登录、登录过期和注销账号时，客户端不删除 FCM Token，也不调用额外的 Token 解绑接口。
- Token 与 UID 的解绑、失效或清理逻辑由服务端处理。
- 同一设备登录新的 UID 后，客户端在新用户登录成功时重新上送当前 FCM Token，由服务端更新 Token 与 UID 的关系。

### 4.4 日志

- Token 获取或上送失败时使用项目 Logger。
- 日志不输出完整 FCM Token。
- 不新增`print`。

## 5. Token 上送接口

### 5.1 注册或更新 Push Token

- 请求：`POST /api/v1/app/push-tokens`
- 鉴权：使用项目 App 业务鉴权

请求 Body：

| 参数 | 类型 | 是否必须 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `fcm_token` | string | 是 | `123e4567-e89b-12d3...` | Firebase 为当前 App 实例生成的 FCM Token，不是项目 Device ID |
| `platform` | string | 是 | `ios` | 平台，只允许`ios`或`android` |

请求示例：

```json
{
  "fcm_token": "123e4567-e89b-12d3...",
  "platform": "ios"
}
```

调用时机：

1. 用户主动登录成功，并取得有效 FCM Token。
2. App 冷启动恢复出有效登录状态，即使本次启动没有执行登录操作，也重新上送当前 FCM Token。
3. 登录状态有效期间，Firebase Messaging 通知 Token 已刷新。

客户端处理：

- Token 为空时不发起请求。
- iOS 上送`ios`，Android 上送`android`。
- iOS 统一上送 FCM Token，不上送 APNs Device Token。
- 每次冷启动恢复登录态后均允许重新上送，服务端负责幂等处理相同 Token。
- Token 刷新后立即重新上送，不受当前页面影响。
- 接口调用失败不阻断登录或页面展示。
- 退出登录、登录过期和注销账号时不调用该接口，也不由客户端清除 Token。
- UID 改变后，在新用户登录成功时重新调用该接口。

## 6. 消息接收

### 6.1 前台消息

- 监听 Firebase Messaging 前台消息。
- 前台消息不在客户端转换为新的本地通知。
- 具体前台 UI 展示方式由后续 UI 需求确定。

### 6.2 后台与终止状态

- 包含 Notification Payload 的远程消息由系统展示。
- App 从后台点击通知时处理消息数据。
- App 从终止状态通过通知启动时处理初始消息。
- 同一条点击消息只处理一次。

## 7. 通知点击

- 客户端读取服务端下发的消息数据并执行页面跳转。
- 跳转字段和值由客户端白名单解析，不直接执行任意路由或 URL。
- 无法识别或缺少跳转数据时进入 App 默认页面。
- 具体 Push Payload 和业务页面映射待服务端协议确认后补充。

## 8. iOS 配置

### 8.1 Xcode Capability

Runner Target 开启：

1. `Push Notifications`
2. `Background Modes → Remote notifications`

最终签名产物通过`aps-environment`决定 APNs 环境：

| 安装方式 | APNs 环境 |
| --- | --- |
| Xcode 使用 Development Profile 安装 | Sandbox / development |
| 本地 Release 模式但仍使用 Development Profile | Sandbox / development |
| TestFlight | Production |
| App Store | Production |
| Ad Hoc / Distribution Profile | Production |

Flutter 的 Debug 或 Release 编译模式不决定 APNs 环境，Provisioning Profile 才决定最终环境。

### 8.2 APNs 身份验证密钥

开发与生产使用不同密钥：

| 用途 | Environment | Key Restriction |
| --- | --- | --- |
| 开发 | Sandbox | Team Scoped (All Topics) |
| 生产 | Production | Team Scoped (All Topics) |

配置要求：

- 将 Sandbox`.p8`上传至 Firebase 的 Development APNs authentication key。
- 将 Production`.p8`上传至 Firebase 的 Production APNs authentication key。
- 上传时填写对应 Key ID 和 Apple Team ID。
- `.p8`不放入 Flutter 工程、客户端配置或 Git。
- Bundle ID、Apple App ID、Firebase iOS App 和签名 Team 保持一致。

### 8.3 iOS 消息代理

- 项目使用 UIScene 生命周期，Firebase Messaging 的通知代理需要在 AppDelegate 启动阶段完成配置。
- 保持 Firebase Messaging Method Swizzling 开启，不在`Info.plist`中设置`FirebaseAppDelegateProxyEnabled = NO`。

## 9. Android 配置

- 使用对应 Firebase App 的`google-services.json`。
- Android 13 及以上声明并请求`POST_NOTIFICATIONS`权限。
- 配置用于普通 Push 的 Notification Channel。
- Notification Channel ID 发布后保持稳定。
