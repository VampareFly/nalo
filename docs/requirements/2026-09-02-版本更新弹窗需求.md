# 版本更新弹窗需求

## 基本信息

- 日期：2026-09-02
- 文档结构整理日期：2026-09-02
- 当前状态：开发完成，自测中
- 适用平台：iOS、Android
- 接口版本：`/api/v1`
- 实现基准：本文是版本检查触发时机、接口字段、更新类型和弹窗交互的实现依据
- 架构：Flutter + Riverpod + MVVM，调用方向为 View → ViewModel → Repository → Service → Nalo 服务端
- 入口：登录状态确认后，本次冷启动首次进入 Home Tab

## 目标

App 每次冷启动首次进入首页时，异步检查当前设备是否存在可用的新版本。

版本检查不能阻塞首页渲染和交互。服务端决定是否更新、更新类型、更新文案和跳转地址；客户端负责单次启动节流、弹窗展示和外部链接打开。

## 流程顺序

```text
App 冷启动并恢复登录状态
  → 首次进入 Home Tab
  → AppVersionViewModel.checkOnce()
  → Repository 收集版本、平台、设备 ID 和语言
  → GET /api/v1/app/configs/version/check
      ├─ has_update = false → 静默结束
      ├─ 普通更新 → 展示弹窗，可 Update now 或 Maybe later
      ├─ 强制更新 → 展示不可关闭弹窗，仅可 Update now
      └─ 请求或解析失败 → 记录日志，本次启动不重试
```

冷启动后如果先进入 Shop Tab，则第一次切换到 Home Tab 时再执行检查。

## 1. 触发时机与节流

- 登录状态确认并首次进入 Home Tab 时立即异步请求。
- 请求与首页首帧渲染并行，不等待检查结果后再展示首页。
- 每次冷启动最多请求一次，节流状态只保存在当前进程内。
- App 从后台恢复、首页重建、Flutter 子页面返回和重复切换 Tab 均不重复请求。
- 请求失败时本次冷启动不自动重试。
- 请求不显示全局 Loading，不阻止首页操作。
- 服务端返回更新信息时，如果当前 Widget 生命周期暂时不适合展示，则由 Home 页面暂存结果并在可展示时打开弹窗。

## 2. 服务端交互

### 2.1 检查版本

- 请求：`GET /api/v1/app/configs/version/check`
- 鉴权：公开接口，不携带 App Access Token
- 响应结构：使用项目统一响应，版本信息位于 `data`

请求参数：

| 参数 | 类型 | 是否必须 | 来源 | 示例 |
| --- | --- | --- | --- | --- |
| `current_version` | string | 是 | `PackageInfo.version` | `1.2.0` |
| `platform` | string | 是 | 当前运行平台 | `ios` |
| `device_id` | string | 是 | `DeviceIdService` | `abc123` |
| `lang` | string | 是 | 当前系统语言代码 | `en` |

客户端使用的响应字段：

| 字段 | 类型 | 是否必须 | 说明 |
| --- | --- | --- | --- |
| `has_update` | bool | 是 | 是否展示版本更新弹窗 |
| `latest_version` | string | 是 | 服务端目标版本 |
| `update_type` | int | 是 | `1` 普通更新，`2` 强制更新 |
| `release_notes` | string[] | 是 | 更新亮点，客户端最多展示前三条有效内容 |
| `market_url` | string/null | 否 | 应用市场更新地址，优先使用 |
| `download_url` | string/null | 否 | 市场地址缺失时的回退地址 |
| `release_date` | string/null | 否 | 客户端不展示 |

### 2.2 客户端解析规则

- `has_update`、`latest_version`、`update_type` 和 `release_notes` 类型不符合协议时，按响应格式错误处理。
- `release_notes` 过滤非字符串和空字符串，并只展示前三条。
- `market_url` 和 `download_url` 允许缺失或为空；只有可解析且带 Scheme 的地址才进入业务 Model。
- 跳转地址优先使用 `market_url`，缺失时使用 `download_url`。
- `release_date` 不进入客户端业务 Model。
- 客户端不自行比较版本号，也不根据版本号推断是否需要更新。

### 2.3 通用响应与安全约束

- HTTP、业务错误码、响应格式错误和网络异常统一经过项目网络层处理。
- 版本检查异常只记录项目 Logger，不显示错误 Toast，不影响首页。
- 不在日志中记录完整设备标识或带敏感参数的更新地址。
- 接口破坏性字段或结构调整时新增 `/v2`，旧版 `/v1` 保持兼容。

### 2.4 客户端职责

1. 控制每次冷启动只检查一次。
2. 获取当前版本、平台、设备 ID 和系统语言。
3. 根据服务端响应决定是否展示弹窗。
4. 根据 `update_type` 控制弹窗能否关闭。
5. 打开服务端提供的更新地址。
6. 上报更新弹窗曝光和用户操作埋点。

### 2.5 服务端职责

1. 根据当前版本、平台、设备和语言决定是否返回更新。
2. 返回目标版本、更新类型、更新亮点和适用于当前平台的跳转地址。
3. 保证普通更新与强制更新策略正确。
4. 保持 `/v1` 字段类型和含义向后兼容。

## 3. 弹窗 UI

- 顶部展示白色圆形底上的蓝色 Nalo Logo。
- Title：`New version available`。
- Desc：说明升级价值，并弱化展示 `latest_version`。
- 更新亮点最多展示三条。
- 主按钮：`Update now`。
- 次操作：`Maybe later`，仅普通更新显示。
- 不展示发布日期、下载地址、设备、平台或灰度策略等技术字段。
- 更新亮点较长时内容区域允许滚动，按钮保持可操作。

## 4. 普通更新

- `update_type = 1`。
- 允许点击遮罩关闭。
- 允许系统返回操作关闭。
- 展示 `Maybe later`。
- 点击 `Maybe later` 后关闭弹窗，本次冷启动不再展示。
- 点击 `Update now` 后尝试打开更新地址；地址无效或打开失败时展示 Toast，并关闭普通更新弹窗。

## 5. 强制更新

- `update_type = 2`。
- 禁止点击遮罩关闭。
- 拦截系统返回操作。
- 不展示 `Maybe later`。
- 只保留 `Update now`。
- 更新地址无效或打开失败时展示 Toast，并保留强制更新弹窗，允许用户再次操作。

## 6. 更新地址

- 优先使用 `market_url`。
- `market_url` 缺失或非法时回退到 `download_url`。
- 两个地址均不可用时，点击 `Update now` 展示 `Unable to open the update page.`。
- 使用项目已有 `url_launcher` 通过外部应用打开。
- 客户端不拼接 App Store、Google Play 或下载站地址。

## 7. 埋点

- 弹窗实际展示后上报 `app_update_alert_view`。
- 点击 `Update now` 或 `Maybe later` 时上报 `app_update_click`。
- 埋点携带当前版本、目标版本、更新类型、操作和更新 URL。
- 埋点失败不得阻断弹窗操作或外部链接打开。

## 8. 异常与边界 Case

- 首次进入 Home 时版本接口超时、断网或返回业务错误。
- 响应 `data` 缺失或字段类型错误。
- `has_update = false` 但其他更新字段存在。
- `release_notes` 为空、超过三条或包含无效元素。
- `update_type` 不是 `1` 或 `2`。
- `market_url` 非法但 `download_url` 有效。
- 两个更新地址均缺失或无法打开。
- 版本检查完成时 Home 页面暂时不可展示弹窗。
- 普通更新弹窗通过遮罩、返回或 `Maybe later` 关闭。
- 强制更新弹窗收到系统返回或遮罩点击。
- 打开外部市场后重新返回 App，本次冷启动不再次请求版本接口。

## 9. 状态与分层

### View

- `HomePage` 在 Home Tab 首次可见时触发 `checkOnce()`。
- 监听待展示更新状态并打开弹窗。
- 处理普通更新关闭、强制更新拦截、外部链接打开和埋点。

### ViewModel / Provider

- `AppVersionViewModel` 保存本次冷启动是否已经检查。
- 请求失败时记录日志并静默结束。
- 弹窗处理完成后清除待消费结果，避免重复展示。

### Repository

- 获取 `PackageInfo.version`、平台、设备 ID 和系统语言。
- 将完整客户端上下文传给 Service。

### Service

- 组装版本检查请求。
- 使用公开接口配置，不要求登录 Token。
- 将统一响应 `data` 转换为 `AppVersionUpdate`。

### Model

- `AppVersionUpdate` 保存更新类型、更新亮点和更新地址。
- 统一提供 `isForceUpdate` 和更新地址优先级，不在 Widget 中重复判断协议字段。

## 13. 完成标准

- 首页首帧和操作不被版本检查阻塞。
- 每次冷启动最多请求一次版本接口。
- `has_update = false` 时不展示弹窗。
- 普通更新可以稍后处理和关闭。
- 强制更新不能通过遮罩或返回操作关闭。
- 更新亮点最多展示三条有效内容。
- 更新地址按 `market_url`、`download_url` 顺序使用。
- 请求、解析和打开地址失败均不会导致首页不可用。
- 更新弹窗曝光和用户操作按埋点规范上报。
