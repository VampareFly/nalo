# 自有业务 API 网络请求封装需求

## 基本信息

- 日期：2026-08-14
- 协议同步日期：2026-09-02
- 当前状态：基础网络层、公共 Header、统一响应、Session 生命周期和测试/生产 HTTPS Base URL 已接入
- 技术栈：Flutter + Riverpod + Dio
- 调用方向：Widget → ViewModel / Provider → Repository → Service → ApiClient → Dio → Nalo 服务端
- 适用范围：Nalo 自有业务 API
- 不适用范围：`flutter_appauth` 承载的 Shopify 授权页面和 Deep Link；Nalo 服务端的 prepare、exchange 等接口仍使用本网络层

## 1. 目标

为自有业务后端提供统一、轻量的网络请求能力：

- 统一 Base URL、超时和 JSON 请求格式。
- 动态注入公共 Header 和 Access Token。
- 统一解析服务端 `code`、`msg`、`data` 响应包；客户端内部将 `msg` 映射为 `message` 属性。
- 区分业务错误、网络错误、响应格式错误和 Session 过期。
- 支持登录、Token 本地持久化、冷启动 Token 检查和 Refresh Token。
- 日志自动隐藏密码和 Token。
- 日志生成、脱敏或输出失败时不得中断、修改或延迟业务请求。
- Widget 不直接依赖 Dio，也不直接请求接口。

网络层保持轻量，不建设复杂的 Endpoint DSL、通用业务 Model 框架或默认自动重试机制。

Riverpod 3 的 Provider 默认会重试失败的构建。项目在根 `ProviderScope` 使用网络层重试策略：`NetworkException`、`ApiException`、`ResponseFormatException` 和 `SessionExpiredException` 不允许触发 Provider 隐式重试，其他非网络 Provider 异常继续使用 Riverpod 默认行为。未来如需网络自动重试，必须按接口幂等性单独设计。

## 2. 文件结构与职责

网络与认证模块采用 7 个核心文件：

```text
lib/core/network/
  api_client.dart
  api_providers.dart
  dio_provider.dart
  provider_retry_policy.dart

lib/features/auth/
  auth_token.dart
  token_storage.dart
  auth_service.dart
  auth_repository.dart
  auth_session_provider.dart
```

### `api_client.dart`

- 提供 `get`、`post`、`put`、`delete`。
- 解析统一响应包。
- 定义并转换统一异常。
- 记录脱敏后的请求与响应日志。
- 收到 Session 过期业务码时触发全局会话失效事件。

### `api_providers.dart`

- 创建自有业务 API 专用 Dio 和 ApiClient。
- 配置 Base URL、JSON Content-Type 和超时。
- 动态生成并注入公共 Header。
- 通过 Riverpod 组装 TokenStorage、设备信息和 Logger。
- 广播全局 Session 过期事件。

### `auth_token.dart`

- 定义客户端使用的 `AuthToken`。
- 集中解析服务端 Token DTO。
- 将服务端过期字段转换为客户端统一的 `expiresAt`。

### `token_storage.dart`

- 定义 TokenStorage 协议。
- 使用 SharedPreferences 保存 Access Token、Refresh Token 和过期时间。
- 提供读取、完整保存和统一清理能力。
- 为将来替换 Keychain / Android Keystore 保留边界。

### `auth_service.dart`

- 定义 Refresh Token、退出登录和账号注销的具体请求路径、请求字段及 DTO 解析。
- 不负责 Token 持久化或页面状态。

### `auth_repository.dart`

- 编排 AuthService 和 TokenStorage。
- 登录或刷新完全成功后，才保存整组 Token。
- 刷新失败时不覆盖仍有效的旧 Token。

### `auth_session_provider.dart`

- 管理全局登录状态。
- 执行冷启动 Token 检查。
- 处理登录成功、主动退出和 Session 过期。
- 不直接显示 Toast 或操作 BuildContext。

## 3. 环境与基础配置

当前 Base URL：

```text
Test: https://api-test.naloresults.com/
Production: https://api.naloresults.com/
```

Dio 默认配置：

| 配置 | 当前值 |
| --- | --- |
| Content-Type | `application/json` |
| 连接超时 | 30 秒 |
| 发送超时 | 30 秒 |
| 接收超时 | 30 秒 |
| 自动重试 | 网络层异常不启用；非网络 Provider 保留 Riverpod 默认行为 |

自有业务 API 使用独立 Dio。Shopify 授权页面、PKCE 和 Deep Link 由 `flutter_appauth` 处理；Nalo 服务端的 prepare、exchange 及其他 App API 继续使用本网络层。

当前所有构建模式为了联调和抓包临时允许绕过 TLS 证书校验。正式发布前必须按照 Release Checklist 恢复证书校验；该临时能力不能作为生产网络方案保留。

## 4. 公共 Header

每次请求动态生成以下 Header：

| Header | 示例 | 来源 |
| --- | --- | --- |
| `Content-Type` | `application/json` | Dio 默认配置 |
| `Authorization` | `Bearer eyJ...` | TokenStorage |
| `X-App-Version` | `1.0.3` | package_info_plus |
| `X-App-Build` | `100` | package_info_plus |
| `X-Platform` | `ios` / `android` | 当前平台 |
| `X-Device-ID` | `a8d92fxxxx` | DeviceIdService |
| `X-Request-ID` | UUID v4 | 每次请求重新生成 |
| `X-Language` | `zh-CN` / `en-US` | 当前 Locale |
| `X-Timezone` | `Asia/Shanghai` | flutter_timezone |

登录和 Refresh Token 请求不添加 `Authorization`，但仍携带其他公共 Header。

## 5. 统一响应协议

成功响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {}
}
```

失败响应：

```json
{
  "code": 4000001,
  "msg": "Invalid parameter",
  "data": null
}
```

响应规则：

1. `code == 0`：只在成功时调用对应业务 DTO decoder。
2. Session 失效业务码：清理本地 Token，不调用 refresh，不重放原请求，并广播全局会话失效事件。
3. 其他非零业务码：将服务端 `msg` 映射为客户端 `message`，并抛出 `ApiException(code, message, data)`。
4. 响应结构缺失或字段类型错误：抛出 `ResponseFormatException`。

HTTP 当前可能仍返回 `200`，客户端以业务 `code` 判断业务成功或失败。

错误码范围：

| 范围 | 模块 |
| --- | --- |
| `1000000+` | 认证、登录、用户 |
| `2000000+` | 待服务端定义 |
| `4000000+` | 参数类错误 |
| `5000000+` | 系统错误 |

## 6. 异常分类

### `ApiException`

服务端已经返回合法响应，但业务 `code != 0`。ViewModel 通常通过客户端异常的 `message` 属性展示服务端 `msg`。

### `NetworkException`

请求没有正常获得业务响应，至少区分：

- 连接、发送或接收超时。
- 无法连接服务器。
- 用户主动取消请求。
- 其他 Dio 传输错误。

### `ResponseFormatException`

服务端 JSON 不符合约定，例如缺少 `code`、Token 字段类型错误或成功响应缺少必要 `data`。

### `SessionExpiredException`

服务端返回以下任一业务码时视为 Session 失效：

- `1000001`
- `1000010`
- `1000011`
- `1000013`

网络层幂等清理 Token 并广播全局事件；应用根部统一进入未登录状态并提示重新登录。

网络层不得直接显示 Toast 或执行路由跳转。Toast、页面状态和导航由 ViewModel、页面或应用级会话监听器处理。

## 7. Token 与账号接口

旧邮箱密码登录接口已删除。正式登录使用登录注册需求文档定义的 `prepare → flutter_appauth → exchange` 流程；本节只维护登录后的 Token 和账号操作接口。

### Refresh Token

```http
POST /api/v1/app/auth/refresh
Content-Type: application/json
```

```json
{
  "refresh_token": "..."
}
```

### Token 响应

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "access_token": "...",
    "refresh_token": "...",
    "expires_in": 900,
    "expires_at": 1786087969
  }
}
```

客户端统一转换为：

```dart
AuthToken(
  accessToken: '...',
  refreshToken: '...',
  expiresAt: DateTime(...),
)
```

- `expires_in` 表示 Access Token 剩余有效秒数。
- `expires_at` 表示 Access Token 到期时间，使用 Unix 秒级时间戳。
- 客户端使用 `expires_at` 转换 UTC `DateTime` 并作为会话过期判断依据。

### 退出与注销

- `POST /api/v1/app/auth/logout`：退出当前 App Session。
- `POST /api/v1/app/auth/deactivate`：永久注销当前账号。
- 退出无论服务端结果如何都清理本地 Session；注销仅在服务端成功后清理。

## 8. Token 本地存储

本阶段使用 SharedPreferences 保存：

- Access Token。
- Refresh Token。
- UTC 过期时间。

TokenStorage 规则：

- 三个字段全部存在且有效时才返回 AuthToken。
- 任一字段缺失或过期时间无法解析时，按无完整 Session 处理。
- 登录和刷新请求完全成功后才整体保存新 Token。
- 主动退出或 Token 已过期时统一调用 `clear()`。

当前阶段继续使用 `SharedPreferences`，不迁移 iOS Keychain / Android Keystore。TokenStorage 已保留抽象边界，未来如调整存储方案不影响 Repository 和网络层调用方式。

## 9. 冷启动 Token 检查

```text
读取本地 Token
  ├─ 无完整 Token → 未登录
  ├─ Token 已过期 → 清空 Token → 未登录 → 提示重新登录
  ├─ Token 未过期且剩余有效期 < 1 天 → 先恢复登录态，后台静默调用 refresh
  │    ├─ 成功 → 保存新 Token → 已登录
  │    └─ 失败 → 保留仍有效的旧 Token → 已登录，不提示
  └─ 剩余有效期 >= 1 天 → 已登录
```

冷启动之外暂不实现：

- Timer 定时刷新。
- App 恢复前台时刷新。
- 普通请求前预刷新。
- 业务请求失败后的自动刷新和请求重放。

## 10. 请求重试策略

当前所有请求均不自动重试。网络错误、弱网、连接失败或超时会转换为 NetworkException，由 ViewModel 决定是否提示用户手动重试。

原因：

- GET 通常可以安全重试。
- 登录、下单、支付、提交检测结果等 POST 可能产生重复业务数据。
- PUT 和 DELETE 是否安全重试取决于服务端幂等设计。
- 业务错误、Token 过期和响应解析错误不应重试。

未来如需增加重试，应由具体接口显式声明，并至少满足：

- 默认只允许幂等 GET 自动重试。
- 只重试连接失败、超时或明确的 `502`、`503`、`504`。
- 采用有限次数和退避间隔。
- 写请求必须有服务端幂等键后才能开启。
- Session 失效码、其他业务错误和取消请求不得重试。

`connectivity_plus` 只能表示设备存在网络接口，不能证明服务端可访问，不能代替 Dio 的实际请求结果。

## 11. 业务接口调用示例

假设获取当前用户资料：

```http
GET /api/v1/app/user/profile
```

### Model

```dart
class UserProfile {
  const UserProfile({
    required this.id,
    required this.email,
    required this.nickname,
  });

  final int id;
  final String email;
  final String nickname;

  factory UserProfile.fromJson(Map<String, dynamic> json) {
    return UserProfile(
      id: json['id'] as int,
      email: json['email'] as String,
      nickname: json['nickname'] as String,
    );
  }
}
```

### Service

```dart
class UserService {
  const UserService(this._apiClient);

  final ApiClient _apiClient;

  Future<UserProfile> getProfile() async {
    final profile = await _apiClient.get<UserProfile>(
      '/api/v1/app/user/profile',
      decoder: (data) => UserProfile.fromJson(
        data! as Map<String, dynamic>,
      ),
    );

    if (profile == null) {
      throw const ResponseFormatException(
        'The profile response has no data.',
      );
    }
    return profile;
  }
}
```

`requiresAuth` 默认是 `true`，因此调用方不需要自己添加 Authorization 和公共 Header。

公开接口或其他无需 Access Token 的请求必须显式设置：

```dart
await apiClient.get<AppVersionUpdate>(
  '/api/v1/app/configs/version/check',
  queryParameters: requestParameters,
  decoder: decodeVersionUpdate,
  requiresAuth: false,
);
```

### Repository

```dart
class UserRepository {
  const UserRepository(this._service);

  final UserService _service;

  Future<UserProfile> getProfile() => _service.getProfile();
}
```

### Riverpod

```dart
final userProfileProvider = FutureProvider.autoDispose<UserProfile>((ref) async {
  final repository = await ref.watch(userRepositoryProvider.future);
  return repository.getProfile();
});
```

### Widget

```dart
final profile = ref.watch(userProfileProvider);

return profile.when(
  loading: () => const CircularProgressIndicator(),
  error: (error, _) => Text(errorMessage(error)),
  data: (user) => Text(user.nickname),
);
```

Widget 只负责监听状态和渲染 UI，不直接持有 Dio 或解析后端响应。

## 12. 日志与安全

请求与响应日志必须隐藏：

- `Authorization`。
- `password`（兼容历史字段和潜在敏感请求）。
- `access_token`。
- `refresh_token`。
- Shopify OAuth 的 `code`、`code_verifier`、`state` 和 `auth_attempt_id`。

日志只能使用项目现有 Logger，不新增 `print`。脱敏只作用于日志副本，不得修改真实请求数据。

### 日志不影响业务请求

- 日志是可降级的辅助能力，不是请求成功的前置条件。
- 日志代码不得取消请求、把请求转为错误，或阻止 Dio Interceptor 继续调用 `handler.next(...)`。
- 请求 URL 格式化、Query 转换、Header/Body 脱敏和 Logger 输出必须使用安全降级边界。其中任一步抛出异常时，忽略本次日志并继续业务请求。
- Query 日志化必须兼容 `String`、`num`、`bool`、`null` 和集合值，不能把 Dio 支持的参数类型直接交给限制更严格的 `Uri.queryParameters`。
- 日志降级不得使用 `handler.reject(...)`。只有 Token/Header 等真实请求上下文初始化失败时，才允许中止请求。
- 请求日志、响应日志和错误日志都遵循相同的非阻断规则。
- 日志失败不得改变页面 Loading、错误文案、重试次数或业务异常类型。

## 13. 测试关注点

由开发者自行决定执行测试、analyze、编译或构建的时机。建议覆盖：

- 成功响应、业务失败和响应格式错误。
- Dio 异常到 NetworkException 的转换。
- 公共 Header 和 Bearer Token 注入。
- prepare、exchange、Refresh 和其他公开请求按协议不携带 Access Token。
- 密码、Authorization 和双 Token 日志脱敏。
- 日志 URL 格式化兼容字符串、整数、布尔值、空值和集合 Query 参数。
- 主动让请求、响应、脱敏或 Logger 格式化抛出异常，确认业务请求和响应处理仍继续执行。
- Token 完整保存、读取和清理。
- 冷启动无 Token、已过期、一天内过期和一天外过期。
- 冷启动刷新失败时保留旧 Token且不提示。
- 任一 Session 失效业务码返回时幂等清理 Token，并统一进入未登录状态。
- Shopify OAuth 请求链路不受影响。
- Release 构建恢复 TLS 证书校验，不保留联调抓包绕过能力。
