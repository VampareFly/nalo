# Nalo GA4 跨端埋点设计

## 基本信息

- 日期：2026-09-10
- Bundle ID 属性补充日期：2026-09-16
- 当前状态：App 端第一阶段已实现，待联调与自测
- 数据平台：Google Analytics 4 + Firebase Analytics + Shopify Google & YouTube
- 并行平台：Amplitude Analytics
- 埋点版本：`v1.0.0`
- 事件基准：App 事件名称、业务属性和触发规则继续以《2026-08-20-客户端埋点设计》为第一准则
- Shopify Web 事件基准：事件名称、参数和触发规则以《2026-09-11-Shopify-Web-GA4埋点设计》为第一准则
- 架构：Flutter + Riverpod + MVVM，App 通过统一 Analytics 封装同时发送 Amplitude 和 GA4

## 目标

本文定义 Nalo App、Shopify Web 和 GA4 之间的数据流转、身份规则、事件映射、参数过滤和环境配置。

本文不重复维护现有客户端全部事件的触发时机。App 事件发生变化时，先更新《2026-08-20-客户端埋点设计》；仅涉及 GA4 平台差异、跨端映射或过滤规则时，更新本文。

当前目标：

- 保留现有 Amplitude 埋点及其事件、参数和身份逻辑。
- App 将现有事件以相同事件名额外发送到 GA4。
- Shopify Google & YouTube 继续提供标准 GA4 Web 和电商事件。
- Shopify Customer Events 额外发送 `shopify_web_*` 链路事件，补充统一 `user_id`、`app_user_id` 和 `journey_id`。
- App、iOS、Android 和 Shopify Web 最终进入同一个业务 GA4 Property。
- Test 和 Production 最终使用不同的 Firebase Project 与 GA4 Property。

## 整体流转

```text
Flutter Widget / ViewModel / NavigatorObserver
  → AnalyticsEvent / AnalyticsEventProperty
  → CompositeAnalyticsService
      ├─ AmplitudeAnalyticsService
      │   → 原事件名 + 原始参数 + App 用户 ID
      └─ FirebaseAnalyticsService
          → 相同事件名 + GA4 参数策略 + Shopify Customer ID

App 点击商品并打开外部浏览器
  → 服务端 Shopify URL 携带 app_user_id + journey_id
  → Shopify Web
      ├─ Google & YouTube 标准事件：电商报表与广告归因
      └─ Customer Events shopify_web_* 事件：user_id / app_user_id / journey_id 链路分析
  → GA4 Test / Production Property
```

任一分析平台上报失败只记录 Logger，不得阻断另一个平台，也不得阻断登录、检测、网络请求、外部跳转或其他业务流程。

## 1. 范围与基本原则

### 1.1 Amplitude 保持不变

- Amplitude 继续使用现有事件名、全部事件参数、公共属性和用户属性。
- Amplitude `user_id` 继续使用 Nalo App 后端用户 `AppUserInfo.id`。
- 本期不删除 `amplitude_flutter`，不迁移 Amplitude 历史数据。
- GA4 参数过滤不得影响发送给 Amplitude 的参数。

### 1.2 App GA4 镜像规则

- App GA4 使用与现有 Amplitude 相同的事件名。
- App GA4 沿用现有事件触发时机和曝光去重规则，不重复增加业务触发点。
- 现有 `page_view` 原样发送到 GA4，不额外发送 `screen_view`。
- 本期不把 `sku_view`、`sku_click` 等现有事件自动改名为 GA4 推荐事件。
- `view_item_list`、`select_item` 等 GA4 推荐电商事件如需增加，作为后续独立需求设计，不改变现有镜像事件。

### 1.3 Shopify 双层事件

Shopify Web 同时保留两层数据：

| 数据层 | 发送方 | 用途 |
|---|---|---|
| 标准层 | Google & YouTube | GA4 电商报表、收入、商品表现、Google Ads 与官方 Checkout 兼容 |
| 链路层 | Shopify Customer Events | 补充统一身份、`journey_id` 和 App → Shopify 路径 |

Customer Events 链路层不得使用与 Google & YouTube 相同的标准事件名，避免同一个 GA4 Property 重复计算电商事件。

Shopify Web 的完整事件、参数、身份、sessionStorage、隐私和验收规则见《2026-09-11-Shopify-Web-GA4埋点设计》。本文只维护跨端约束，不重复维护每个 Shopify 事件的详细参数表。

## 3. App 双写架构

### 3.1 调用流转

```text
业务层
  → AnalyticsService.report
  → CompositeAnalyticsService
      ├─ AmplitudeAnalyticsService.report
      └─ FirebaseAnalyticsService.report
```

业务页面继续只依赖 `AnalyticsService`，不得直接调用 `Amplitude` 或 `FirebaseAnalytics` SDK。

### 3.2 服务职责

| 类型 | 职责 |
|---|---|
| `AnalyticsService` | 对业务层暴露统一事件、页面、身份和用户属性接口 |
| `CompositeAnalyticsService` | 将同一次操作分发给 Amplitude 与 Firebase，隔离单个平台失败 |
| `AmplitudeAnalyticsService` | 保持现有 Amplitude 行为 |
| `FirebaseAnalyticsService` | 发送同名 GA4 事件、应用 GA4 参数策略并管理 GA4 身份 |
| `Ga4ParameterPolicy` | 强制移除禁止字段，并保留未来参数白名单入口 |
| `AnalyticsUserIdentity` | 同时携带 App 用户 ID 和 Shopify Customer ID，由不同平台选择对应身份 |

### 3.3 事件分发规则

- 两个平台独立执行、独立捕获异常。
- 一个平台失败不能取消另一个平台的发送。
- 业务层等待 Analytics 时，只等待分发结束，不对外抛出 SDK 异常。
- Logger 只记录事件名、平台和异常，不记录完整参数值，避免敏感信息进入日志。

## 5. GA4 参数策略

### 5.1 当前阶段

当前阶段除明确禁止字段外，其他现有业务事件参数全部允许发送到 GA4，不启用完整白名单限制。

强制禁止以下参数：

| 参数 | 禁止原因 |
|---|---|
| `email` | 可识别个人的信息，不得进入 GA4 普通事件参数 |
| `name` | 可识别个人的信息，不得进入 GA4 普通事件参数 |
| `birth` | 完整生日属于个人信息，不得进入 GA4 普通事件参数 |
| `x-idfa` | 不得把广告标识符作为自定义事件参数或用户属性发送 |

禁止规则只作用于 Firebase Analytics。Amplitude 仍按原设计发送这些字段。

### 5.2 过滤入口

GA4 参数策略集中维护，不在 Widget 或 ViewModel 中分散判断。设计形态：

```dart
abstract final class Ga4ParameterPolicy {
  static const blockedParameterNames = <String>{
    'email',
    'name',
    'birth',
    'x-idfa',
  };

  static Map<String, Object> sanitize(
    Map<String, Object> parameters,
  ) {
    // TODO: <pf> 根据最终 GA4 数据规范启用业务参数白名单。
    // 当前除强制禁止字段外，其他业务参数暂时全部放行。
    return Map.fromEntries(
      parameters.entries.where(
        (entry) => !blockedParameterNames.contains(entry.key),
      ),
    );
  }
}
```

后续白名单规则可以预留在同一类型中，但在确认字段范围前保持注释状态，不影响当前业务参数发送。

### 5.3 公共属性的平台差异

| 当前公共属性 | Amplitude | GA4 App |
|---|---|---|
| `notification_enabled` | 每个事件发送 | 当前阶段随事件发送，可后续评估用户属性化 |
| `platform` | 每个事件发送 | 当前阶段可镜像；报表优先使用 GA4 内置 Platform |
| `app_version` | 每个事件发送 | 当前阶段可镜像；报表优先使用 GA4 内置 App version |
| `bundle_id` | 每个事件发送 | 每个事件发送，值为 iOS Bundle ID / Android Application ID |
| `os_version` | 每个事件发送 | 当前阶段可镜像；报表优先使用 GA4 内置 OS version |
| `user_id` | 普通事件属性并绑定 Amplitude 身份 | 不作为普通事件参数，使用 GA4 系统 `user_id` |
| `app_user_id` | 不额外增加，现有 `user_id` 已表达 App 身份 | 作为用户属性发送 App 后端用户 ID，仅用于调试和身份排查 |
| `kc_id` | 每个事件发送 | 当前阶段业务参数放行规则不自动添加该字段；后续不得注册为高基数自定义维度 |

`user_id` 是 GA4 系统身份字段，不进入自定义参数白名单，也不注册为自定义维度。

`shop_shopify_url_request` 在 Amplitude 中继续遵循客户端埋点文档的原始 `url` 规则。镜像到 GA4 时不得发送完整 Query 与 Fragment，只保留 `origin + pathname`，避免 App Journey ID 或其他查询参数进入 GA4 页面地址和高基数自定义参数。

## 6. 用户身份与用户属性

### 6.1 两个平台使用不同身份

接口用户示例：

```json
{
  "id": 1,
  "is_profile_completed": 1,
  "email": "user@example.com",
  "full_name": "John",
  "gender": 1,
  "shopify_customer_id": 1
}
```

身份规则：

| 平台 | 身份来源 | 示例 |
|---|---|---|
| Amplitude | `AppUserInfo.id` | `1` |
| GA4 App | `AppUserInfo.shopifyCustomerId` | `1` |
| Shopify Customer Events | `init.data.customer.id` 或可信服务端映射 | `1` |

GA4 统一格式：

`shopify_customer_id` 转为字符串后原样使用，不增加业务前缀。

App 与 Shopify Web 必须使用完全相同的格式。不得使用邮箱、姓名或手机号构造 GA4 `user_id`。

### 6.2 模型与持久化

`AppUserInfo` 增加可空 `shopifyCustomerId`，并在 `fromJson()`、`toJson()` 和当前用户快照中持久化。

该字段属于分析身份，不得因字段缺失、类型异常或非正数阻断登录。无有效 Shopify Customer ID 时：

```text
Amplitude → 正常设置 App 用户 ID
GA4 → 不设置 user_id
业务登录 → 正常完成
Logger → 仅记录身份缺失，不记录用户资料
```

### 6.3 生命周期

登录成功：

```text
取得 AppUserInfo
  → Amplitude setUserId(AppUserInfo.id)
  → GA4 setUserId(shopifyCustomerId)
  → 设置各平台允许的用户属性
  → 上报 login_request_result
```

冷启动恢复：

```text
读取 Token 与 AppUserInfo 本地快照
  → Token 有效
  → 恢复 Amplitude App 用户 ID
  → 恢复 GA4 Shopify Customer ID
  → 再进入业务页面并发送后续事件
```

退出、Token 失效或注销：

```text
Amplitude → reset()
GA4 → setUserId(null)
```

GA4 设置身份只影响设置后的事件，不回填之前已经采集的事件。

### 6.4 用户属性

| 用户属性 | Amplitude | GA4 App | Shopify Web GA4 |
|---|---|---|---|
| App 用户 `user_id` | 使用 | 以 `app_user_id` 用户属性发送，用于调试和身份排查 | App 来源时以相同 `app_user_id` 用户属性发送；无有效 Journey 时清空 |
| Shopify Customer ID | 不改变现有逻辑 | 仅作为系统 `user_id` | 仅作为相同格式的系统 `user_id`，不作为自定义用户属性 |
| `login_status` | 使用 | 允许作为低基数用户属性 | 不使用；Web 登录状态使用 `shopify_login_state` |
| `notification_permission` | 使用 | 允许作为低基数用户属性 | 不使用 |
| `bundle_id` | 使用 | 使用，启动准备、登录成功或冷启动恢复身份时设置 | 不使用 |
| `shopify_login_state` | 不使用 | 不使用 | `logged_in` / `anonymous` |
| `app_linked_user` | 不使用 | 不使用 | 当前存在有效 App Journey 时为 `yes`，否则为 `no` |
| `kc_id` | 使用 | 不设置为 GA4 用户属性 | 不使用 |
| `x-idfa` | 使用 | 强制禁止作为 GA4 自定义用户属性 | 不使用 |

`entry_source` 属于事件和 Journey 维度，不设置为用户属性。Shopify Web 不使用 `latest_entry_source` 用户属性，避免后一次访问覆盖历史来源语义。

## 7. Shopify Google & YouTube 自动事件

Google & YouTube 当前将 Shopify 标准事件映射为以下 GA4 事件：

| Shopify Customer Event | GA4 自动事件 | 主要参数 |
|---|---|---|
| `page_viewed` | `page_view` | `page_location`, `page_title`, `shopify_event_name`, `event_id` |
| `collection_viewed` | `view_item_list` | `item_list_id`, `item_list_name`, `items` |
| `product_viewed` | `view_item` | `currency`, `value`, `items` |
| `cart_viewed` | `view_cart` | `currency`, `value`, `items` |
| `product_added_to_cart` | `add_to_cart` | `currency`, `value`, `items` |
| `product_removed_from_cart` | `remove_from_cart` | `currency`, `value`, `items` |
| `checkout_started` | `begin_checkout` | `currency`, `value`, `coupon`, `items` |
| `checkout_address_info_submitted` / `checkout_shipping_info_submitted` | `add_shipping_info` | `currency`, `value`, `shipping`, `tax`, `items` |
| `payment_info_submitted` | `add_payment_info` | `currency`, `value`, `payment_type`, `items` |
| `checkout_completed` | `purchase` | `transaction_id`, `currency`, `value`, `tax`, `shipping`, `coupon`, `items` |

Google Tag 还会产生 `first_visit`、`session_start` 和 `user_engagement`。这些不是 Shopify 电商业务事件，不在 Customer Events 中重复发送。

Google & YouTube 自动事件当前没有公开入口供 Nalo 动态设置自定义 GA4 `user_id`。Customer Events 中设置的身份不得假设会影响 Google & YouTube 的独立自动事件。

### 8.1 映射表

| Shopify Customer Event | Google & YouTube 标准事件 | Nalo Shopify Web 链路事件 |
|---|---|---|
| `page_viewed` | `page_view` | `shopify_web_page_view` |
| `collection_viewed` | `view_item_list` | `shopify_web_collection_view` |
| `product_viewed` | `view_item` | `shopify_web_product_view` |
| `search_submitted` | `search` | `shopify_web_search` |
| `product_added_to_cart` | `add_to_cart` | `shopify_web_add_to_cart` |
| `product_removed_from_cart` | `remove_from_cart` | `shopify_web_remove_from_cart` |
| `cart_viewed` | `view_cart` | `shopify_web_cart_view` |
| `checkout_started` | `begin_checkout` | `shopify_web_checkout_start` |
| `checkout_contact_info_submitted` | 无直接对应 | `shopify_web_checkout_contact_submit` |
| `checkout_address_info_submitted` | `add_shipping_info` | `shopify_web_checkout_address_submit` |
| `checkout_shipping_info_submitted` | `add_shipping_info` | `shopify_web_checkout_shipping_submit` |

| `alert_displayed` | 无直接对应 | `shopify_web_alert_display` |
| `ui_extension_errored` | 无直接对应 | `shopify_web_ui_extension_error` |

`shopify_web_app_entry` 是基于 `page_viewed` 和 URL 中一对新的 `app_user_id + journey_id` 衍生的入口事件，不是 Shopify 标准事件。同一个 `journey_id` 在当前浏览器会话只发送一次。

### 8.2 链路公共参数

所有 Nalo Shopify Web 链路事件统一补充：

| 参数 | 类型 | 规则 |
|---|---|---|
| `event_platform` | String | 固定 `shopify_web` |
| `event_schema_version` | String | 当前固定 `1` |
| `entry_source` | String | 同时存在有效 `app_user_id + journey_id` 时为 `app`，否则为 `standalone_web` |
| `app_user_id` | String | Nalo App 后端用户 ID；非 App 来源无值不传 |
| `journey_id` | String | 本次 App → Shopify 购物旅程 ID；非 App 来源无值不传 |
| `shopify_event_id` | String | `event.id` |
| `shopify_event_seq` | Number | `event.seq` |
| `shopify_client_id` | String | `event.clientId` |
| `page_location` | String | 仅 origin + pathname，不发送 Query 与 Fragment |
| `page_path` | String | 当前页面 pathname |
| `page_type` | String | `home`、`product`、`collection`、`search`、`cart`、`checkout`、`account`、`content` 或 `other` |
| `shopify_customer_id` | String | Shopify 能识别 Customer 时发送；不注册自定义维度 |

`event_platform` 表示事件实际发生位置。即使存在 App Journey，Shopify Web 事件仍为 `shopify_web`；入口来源由 `entry_source` 表示。

### 8.3 电商参数

商品事件尽量使用一致结构：

```text
currency
value
items[].item_id
items[].item_name
items[].item_variant
items[].item_brand
items[].price
items[].quantity
```

`item_id` 统一优先使用 Shopify Variant ID。需要保留商品与规格关系时额外携带 `product_id` 和 `variant_id`。

购买完成事件额外携带：

```text
transaction_id
tax
shipping
coupon
```

Customer Events 链路事件使用 `shopify_web_*` 名称，这些参数用于路径和 BigQuery 分析，不作为第二套 GA4 标准电商事件计算。完整 Item、Cart、Checkout、Order 和每个事件的参数来源见《2026-09-11-Shopify-Web-GA4埋点设计》；本文不重复维护。

|---|---|---|---|
| GA4 `user_id` | `<shopify_customer_id>` | `<shopify_customer_id>` | 长期登录身份；存在时跨 Stream 合并 |
| `app_user_id` | App 后端用户 ID 用户属性 | URL 取得后保存为用户属性并附加到 App 来源事件 | 关联 Nalo App 用户 |
| `journey_id` | 打开 Shopify 前生成或取得 | 与 `app_user_id` 成对保存并在后续链路中恢复 | 串联一次 App → Shopify 购物旅程 |
| `product_id` | App 商品模型 | Shopify Product ID | 商品关联 |
| `variant_id` | App 商品模型 | Shopify Variant ID | 规格与购买项关联 |
| `item_id` | 推荐使用 Variant ID | 推荐使用 Variant ID | GA4 电商 Item 主键 |
| `currency` | 商品币种 | 购物与订单币种 | 金额解释 |
| `value` | 对应事件金额 | 对应事件金额 | 行为与订单价值 |
| `event_platform` | App 侧不强制新增，报表优先使用 GA4 内置 Platform | `shopify_web` | Shopify 自定义事件实际发生位置 |
| `entry_source` | 不使用 | `app` / `standalone_web` | Shopify Journey 的入口来源 |

同名字段在 App 与 Web 中必须保持相同类型和语义。

## 10. App → Shopify 完整链路

### 10.1 App 侧

```text
sku_view
→ sku_click
→ shop_shopify_url_request
→ 外部浏览器打开
```

服务端 Shopify URL 返回需要稳定提供 `app_user_id` 和 `journey_id`。推荐响应显式返回：

```json
{
  "url": "https://shop.example.com/products/example?app_user_id=1&journey_id=J100",
  "app_user_id": "1",
  "journey_id": "J100"
}
```

App 不应依赖解析 URL 才获得 Journey 参数。现有接口尚未显式返回时，可暂时从 URL 读取，并在服务端协议更新后迁移。GA4 不发送包含 Query 和 Fragment 的完整 Shopify URL。

### 10.2 Web 侧

```text
shopify_web_app_entry
→ shopify_web_page_view
→ shopify_web_product_view
→ shopify_web_add_to_cart
→ shopify_web_cart_view
→ shopify_web_checkout_start
→ shopify_web_checkout_address_submit
→ shopify_web_checkout_shipping_submit
→ shopify_web_payment_info_submit
→ shopify_web_purchase
```

首次从 URL 同时取得 `app_user_id + journey_id` 后保存到 `browser.sessionStorage`，后续链路事件成对恢复使用。同一个浏览器会话内不因返回首页、查看其他商品或继续结账而丢失。只有一个参数时不得保存半条链路。

### 10.3 订单兜底

`app_user_id` 和 `journey_id` 同时写入 Cart/Checkout/Order custom attribute。前端 Pixel 因 consent、页面关闭、广告拦截或网络异常丢失时，订单侧仍可完成最终归因。

```text
app_user_id + journey_id
  → App 事件
  → Shopify 链路事件
  → Cart / Order attribute
  → transaction_id
```

## 11. GA4 数据查看

### 11.1 聚合报表

- 默认报表包含同一 Property 下所有 Stream。
- 使用 `Platform` 区分 iOS、Android 与 Web。
- 使用 `Stream name` / `Stream ID` 区分具体数据流。
- Google & YouTube 标准事件用于 Monetization 与 Ecommerce 报表。
- App 同名自定义事件和 `shopify_web_*` 链路事件用于 Events、Explorations 和路径分析。

### 11.2 用户与路径

- GA4 Reporting identity 需要使用包含 User-ID 的模式。
- User Explorer 可查看有效用户 ID 对应的事件时间线，但不作为业务后台按原始 ID 检索的唯一工具。
- `user_id` 只合并携带相同 ID 的后续事件，不回填设置前事件。
- iOS、Android 和 Web 的 Session 仍是独立 Session；统一 `user_id` 不等于延续同一个 Session。
- 精确按 `user_id`、`journey_id` 和 `transaction_id` 查询完整路径时使用 BigQuery Export。

### 11.3 自定义定义

- 不把 `user_id`、`app_user_id`、`journey_id`、`shopify_customer_id` 等高基数 ID 注册为普通自定义维度。
- 低基数字段如 `event_platform`、`entry_source`、`page_type`、`login_status`、`shopify_login_state` 和 `app_linked_user` 可以按报表需求注册。
- 自定义定义创建前先确认使用场景，避免 Property 配额浪费和 `(other)` 聚合。

## 13. Shopify 实现限制

- Customer Events 必须遵循 Shopify Customer Privacy 配置；未获得对应 Analytics consent 时不得绕过 Shopify 的数据收集限制。
- `init.data.customer.id` 只有 Shopify 能识别当前客户且数据权限允许时才存在。
- App 已登录不代表外部浏览器已经登录 Shopify；无法取得 Customer ID 时使用 `app_user_id + journey_id` 串联本次旅程。
- Custom Pixel 中设置的 `user_id` 只作用于其自行发送的事件，不假设影响 Google & YouTube 自动事件。
- Google 当前不把 Custom Pixel 内运行 Google Tag 视为受支持的 Shopify Google Tag 实现，Checkout 与 Post-checkout 的行为和数据完整性需要专项验证。
- 不允许 Customer Events 使用标准事件名重复发送 Google & YouTube 已发送的事件。
- Customer Events 使用 `browser.sessionStorage` 保存 App Journey；返回首页和继续浏览不会主动清除，会话结束后自然失效。
- Custom Pixel 只读取 Cart/Checkout attributes，不承担修改购物车或订单的业务职责。

## 14. 维护规则

新增或修改 App 事件时：

1. 在《2026-08-20-客户端埋点设计》中维护事件名、属性、触发时机和枚举。
2. 默认由组合服务自动镜像到 GA4。
3. 检查是否包含 `Ga4ParameterPolicy` 强制禁止字段。
4. 涉及敏感数据时先确认 GA4 数据用途，再决定是否加入允许范围。
5. 涉及 App → Shopify 路径时同步更新本文的跨端映射。

新增或修改 Shopify 链路事件时：

1. 记录原始 Shopify Customer Event。
2. 确认 Google & YouTube 是否已发送对应标准事件。
3. 使用唯一 `shopify_web_*` 事件名，避免标准事件重复。
4. 复用链路公共参数和电商 Item 结构。
5. 同步检查 Cart/Order attribute 与 BigQuery 查询关联字段。
