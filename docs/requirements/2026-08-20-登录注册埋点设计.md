# 登录注册埋点设计

## 1. 文档说明

本文是 Nalo Flutter 项目登录注册流程的埋点定义和客户端实现设计，后续代码以本文为依据。

范围仅包括进入首页之前的流程：

```text
App 启动
→ AuthGate 认证分流
→ 登录注册入口
→ Shopify 登录
→ 创建账号资料
→ Welcome
→ 进入 Home
```

埋点版本统一为：

```text
v1.0.0
```

事件名和属性名统一使用 `snake_case`。本文档中的事件名称、属性名称、类型和枚举值为第一准则。

## 2. 当前页面与路由

| 页面 | Page Name | Flutter 页面 | 路由 |
|---|---|---|---|
| 登录注册入口 | `login_sign_in` | `AuthEntryPage` | `/auth` |
| 创建账号 | `create_account` | `AccountProfilePage` | `/account-profile` |
| Welcome | `welcome` | `OnboardingWelcomePage` | `/onboarding-welcome` |

`AuthGatePage` 只负责启动认证分流，没有业务 UI，不上报 `page_view`。

## 3. 事件埋点

### 3.1 Page View

| 事件名 | 版本 | 页面 | 触发时机 | 属性名 | 数据类型 | 属性值说明 | 端 |
|---|---|---|---|---|---|---|---|
| `page_view` | v1.0.0 | 所有已定义页面 | 每次页面进入或返回重新可见 | `page_name` | String | 页面名称枚举 | 客户端 |
| `page_view` | v1.0.0 | 所有已定义页面 | 每次页面进入或返回重新可见 | `previous_page` | String | 上一个页面名称；没有时为空字符串 | 客户端 |

触发规则：

- 页面首次进入时上报。
- 从下一级页面返回时再次上报。
- `previous_page` 使用 Page Name 枚举值。
- 页面曝光通过路由观察器统一处理，不依赖 Widget 的 `initState()`。

### 3.3 登录请求结果

| 事件名 | 版本 | 页面 | 触发时机 | 属性名 | 数据类型 | 属性值说明 | 端 |
|---|---|---|---|---|---|---|---|
| `login_request_result` | v1.0.0 | `login_sign_in` | 完整认证流程结束 | `login_method` | String | `"1"` Shopify；`"2"` Apple | 客户端 |
| `login_request_result` | v1.0.0 | `login_sign_in` | 完整认证流程结束 | `is_success` | Int | `0` 失败；`1` 成功 | 客户端 |
| `login_request_result` | v1.0.0 | `login_sign_in` | 完整认证流程结束 | `fail_reason` | String | 成功为空字符串；失败为 `code: reason` | 客户端 |

当前项目仅实现 Shopify：

```text
login_method = "1"
```

认证结果以完整流程为准：

```text
prepare
→ Shopify OAuth
→ exchange
→ 保存 Token 和用户快照
→ 得到最终页面分流结果
```

服务端返回 `reason` 时直接使用服务端内容；其他异常由客户端转换为稳定错误码，例如：

```text
network_error: Unable to connect to server
oauth_cancelled: User cancelled Shopify authorization
oauth_error: Shopify authorization failed
session_expired: Session expired
unknown_error: Unknown authentication error
```

## 6. 客户端用户属性

| 版本 | 属性名 | 数据类型 | 设置时机 | 属性值说明 | 端 |
|---|---|---|---|---|---|
| v1.0.0 | `user_id` | String | Shopify exchange 成功并取得服务端用户 ID 后 | 后端稳定用户 ID | 客户端 |
| v1.0.0 | `login_status` | String | 登录成功后 | `"1"` Shopify；`"2"` Apple | 客户端 |
| v1.0.0 | `notification_permission` | String | 通知权限状态确定或变化后 | `"0"` 未开启；`"1"` 已开启 | 客户端 |
| v1.0.0 | `kc_id` | String | 设备 ID 获取成功后；登录识别用户时再次设置 | 钥匙串设备 ID | 客户端 |

```text

```

## 8. Analytics 设计

### 8.1 调用流转

```text
Widget / ViewModel / NavigatorObserver
→ AnalyticsService
→ 公共属性采集
→ Amplitude SDK
```

- Widget 上报用户可见的点击行为。
- ViewModel 上报网络请求和业务结果。
- NavigatorObserver 上报页面曝光和返回曝光。
- Analytics Service 统一转换枚举、添加公共属性和调用 Amplitude。
- 埋点失败只写 Logger，不阻断登录注册主流程。

### 8.2 文件职责

建议继续由 `lib/core/analytics/analytics.dart` 统一维护第一版 Analytics 定义：

| 类型 | 职责 |
|---|---|
| `AnalyticsEvent` | 维护事件名称 |
| `AnalyticsPageName` | 维护 `page_name` 枚举 |
| `AnalyticsEventProperty` | 维护业务事件属性名 |
| `AnalyticsCommonProperty` | 维护自动添加的公共事件属性名 |
| `AnalyticsUserProperty` | 维护 Amplitude 用户属性名 |
| `AnalyticsLoginClickMethod` | 维护登录按钮入口值 `"1"`、`"2"` |
| `AnalyticsLoginMethod` | 维护 Shopify/Apple 值 `"1"`、`"2"` |
| `AnalyticsGender` | 维护 Female/Male 值 `"1"`、`"2"` |
| `AnalyticsService` | 对业务层暴露统一埋点接口 |
| `AmplitudeAnalyticsService` | 使用 Amplitude SDK 完成具体上报 |
| `analyticsProvider` | 通过 Riverpod 注入 Analytics Service |
| `AnalyticsWidgetRef` | 为 Widget 提供简短调用入口 |
| `AnalyticsNavigatorObserver` | 监听页面进入和返回，自动上报 `page_view` |

### 8.3 外部调用方式

Widget 点击事件：

```dart
await ref.report(
  AnalyticsEvent.loginClick,
  properties: {
    AnalyticsEventProperty.method:
        AnalyticsLoginClickMethod.continueWithShopify.value,
  },
);
```

ViewModel 请求结果：

```dart
await ref.read(analyticsProvider).report(
  AnalyticsEvent.loginRequestResult,
  properties: {
    AnalyticsEventProperty.loginMethod: AnalyticsLoginMethod.shopify.value,
    AnalyticsEventProperty.isSuccess: 1,
    AnalyticsEventProperty.failReason: '',
  },
);
```

普通 Dart 类不读取全局 Provider，通过构造函数注入：

```dart
class ExampleService {
  const ExampleService(this._analytics);

  final AnalyticsService _analytics;
}
```

### 8.4 页面曝光职责

`AnalyticsNavigatorObserver` 负责：

- `didPush`：上报新页面的 `page_view`。
- `didPop`：重新上报返回后可见页面的 `page_view`。
- 保存当前 Page Name，作为下一条事件的 `previous_page`。
- 忽略未进入 Page Name 枚举的页面。

页面曝光不直接写在 `initState()`，避免返回页面时漏报。

### 8.5 用户身份生命周期

登录成功顺序：

```text
取得服务端 user_id
→ Amplitude setUserId
→ 设置 user_id、login_status、kc_id
→ iOS ATT 状态确定后设置 x-idfa
→ 上报 login_request_result 成功
```

未登录时公共属性 `user_id` 使用空字符串。

主动退出、Token 失效或注销账号成功时，应在业务会话清理后调用 Amplitude `reset()`；`reset()` 不删除钥匙串中的 `kc_id`。当前项目尚无账号注销接口，后续接入时复用 `resetIdentity()`。

## 10. IDFA 设计

当前项目不新增 Flutter 第三方插件，优先复用平台通道并使用 iOS 官方框架：

```text
AppTrackingTransparency
AdSupport
```

建议流程：

```text
AuthEntryPage 首次展示完成
→ 查询 ATT 状态
→ 尚未决定时请求 ATT
→ 已授权：读取真实 IDFA
→ 拒绝/受限：返回全 0 IDFA
→ 设置 Amplitude 用户属性 x-idfa
```

iOS `Info.plist` 已配置 `NSUserTrackingUsageDescription`；提示文案如需调整，应在发版前由产品确认。

## 12. 数据约束

- 事件名和属性名不得由页面直接编写字符串，统一使用枚举。
- 枚举实际发送值必须与本文一致。
- `is_success` 使用 Int `0`、`1`。
- 通知状态使用 String `"0"`、`"1"`。
- `gender` 使用 String `"1"`、`"2"`。
- `login_method` 和登录入口 `method` 使用 String `"1"`、`"2"`。
- `birth` 使用实际传给服务端的格式。
- 成功请求的 `fail_reason` 使用空字符串。
- 服务端失败优先使用服务端 `reason`，其他异常使用客户端稳定错误码。
- 所有公共事件属性由 Analytics Service 统一生成。
- Analytics 初始化在应用生命周期中只执行一次。
- 埋点异常不得中断页面跳转或登录注册请求。
