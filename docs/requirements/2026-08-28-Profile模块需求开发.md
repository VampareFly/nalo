## 目标

按照 Figma 重新实现登录后的 Profile 模块，负责：

- 主动刷新并展示当前用户资料。
- 展示用户累计完成的检测次数。
- 编辑 Name、Date of birth 和 Biological sex。
- 展示 Shopify 账号连接状态并进入 Shopify 管理页面。
- 提供 Notification、Privacy、Terms 和 Help 的临时入口。
- 提供 Referral、Sign out 和 Delete account 操作。

Profile 不负责修改 Shopify Email。Email 当前只读，后续是否开放修改由服务端和产品另行确认。

## 流程顺序

```text
首页头像
→ Profile
   ├─ Edit → Edit profile
   │          ├─ 服务端返回 4000105 → 阻断弹窗，不允许保存
   │          ├─ 服务端返回 4000106 → 黄色提示 → Continue anyway → 携带 age_confirm: 1 更新资料
   │          └─ 18 至 65 岁 → Save changes → 更新资料
   ├─ Shopify account / Manage → Shopify 管理页面
   ├─ Notification settings → Toast
   ├─ Privacy policy → Toast
   ├─ Terms of service → Toast
   ├─ Help & support → Toast
   ├─ Share referral link → 拉起系统分享面板
   ├─ Sign out → 退出登录 → 登录注册入口
   └─ Delete account → 二次确认 → 注销成功 → 登录注册入口
```

## 1. Profile 入口与初始化

- 首页头像点击后使用 `push` 进入 Profile。
- 每次进入 Profile 时主动调用 `GET /api/v1/app/user/info`，不只使用本地 User 快照。
- 请求期间直接展示本地用户快照或默认占位内容，不展示页面级 Loading；响应返回后自动刷新 UI。
- 请求成功后使用服务端 User 覆盖本地当前用户快照，并刷新 Profile UI。
- 请求失败时保留已有本地 User 快照，检测次数降级为 `0`，并展示可理解的 Toast。
- 返回按钮使用 `pop` 回到进入 Profile 前的页面。
- 页面支持垂直滚动，内容不得因小屏幕或系统字体放大而溢出。

## 2. Profile 页面结构

页面元素按 Figma 顺序排列：

1. 返回按钮、`Profile` 标题和 `Edit` 按钮。
   顶部返回与 Edit 按钮的外边缘分别与下方卡片左右边缘对齐，页面统一使用 20 逻辑像素的水平外边距。
2. `Tests completed` 卡片。
3. Name、Email、Date of birth、Biological sex 信息卡片。
4. Shopify account 卡片和 `Manage` 按钮。
5. Notification settings、Privacy policy、Terms of service、Help & support 入口卡片。
6. Referral 卡片和 `Share referral link` 按钮。
7. `Sign out` 按钮。
8. `Delete account` 按钮。

### 用户信息展示

- Name 使用 `full_name`，去除首尾空格后展示。
- Email 使用 `email`，只读展示。
- Date of birth 使用 `birth_day`。
- Biological sex 根据 `gender` 映射：`1` 为 Male，`2` 为 Female。
- 用户字段为空或异常时展示统一占位文案，不允许将 `null`、空字符串或非法枚举直接显示给用户。
- Email 修改暂不支持，开发时必须使用 `// TODO: <pf>` 标记后续接入事项。

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "id": 1,
    "email": "user@example.com",
    "full_name": "Diana",
    "birth_day": "1990-01-01",
    "gender": 2,
    "is_profile_completed": 1,
    "test_info": {
      "sum_count": 15,
      "cortisol_count": 10,
      "testosterone_count": 5
    },
    "referral_card": {
      "title": "10% off for you both.",
      "description": "Share your link and save together when they place their first order.",
      "button_text": "Share referral link",
      "action_url": "{referral_link}",
      "share_text": "Get 10% off your Nalo test kit with my referral link.",
      "rewards_advocate": {
        "reward_type": "percentage",
        "reward_value": 10,
        "reward_unit": "%"
      },
      "rewards_friend": {
        "reward_type": "store_credit",
        "reward_value": 10,
        "reward_unit": "$"
      }
    }
  }
}
```

- Profile 的 `Tests completed` 使用 `test_info.sum_count`。
- `test_info` 缺失、为 `null`、类型错误，或 `sum_count` 缺失、为负数、类型错误时统一展示 `0`。
- `cortisol_count` 和 `testosterone_count` 当前只解析保留，不在 Profile 页面展示。
- 不使用首页接口的历史总数代替 `sum_count`。

## 4. Edit profile

页面按 Figma 顺序展示：

1. 返回按钮。
2. Nalo Wordmark。
3. `Edit your profile.` 标题。
4. Email。
5. Name。
6. Date of birth。
7. Biological sex。
8. `Save changes` / `Continue anyway` 按钮。
9. 个人信息用途说明。

### Email

- 使用当前 User 的 `email`。
- 暂不允许编辑，输入区域保持只读。
- Email 不包含在 `/user/update` 请求 Body 中。
- 代码中添加 `// TODO: <pf> 服务端支持修改 Email 后开放编辑并补充校验。`

### Name

- 单个输入框，与注册资料页一致，不拆分 First Name 和 Last Name。
- 初始值使用当前 User 的 `full_name`。
- 去除首尾空格后不能为空。
- 最大长度和字符限制继续遵循注册资料页规则。

### Date of birth

- 初始值使用当前 User 的 `birth_day`。
- 点击后打开英文日期选择器。
- 不允许选择未来日期。
- 提交格式固定为 `yyyy-MM-dd`。
- 客户端年龄计算仅用于界面辅助；18岁和65岁限制由 `/user/update` 的服务端错误码决定，并与注册资料页复用同一套确认状态。

### Biological sex

- 只保留 Female 和 Male。
- `Female` 提交 `2`，`Male` 提交 `1`。
- 初始选中状态使用当前 User 的 `gender`。
- 未选择时不允许提交。

## 5. 编辑资料校验与年龄边界

- 只在点击 `Save changes` 或 `Continue anyway` 时进行完整校验。
- 缺少必填项时保留表单内容并展示错误。
- 请求期间显示页面级 Loading，禁止重复提交和返回。
- 更新失败时保留所有编辑内容并展示服务端 `msg`。

### 未满 18 岁

- 首次保存不在本地阻断，请求不携带 `age_confirm`。
- 服务端返回 `4000105` 后不展示 Toast或页面错误文字，只复用注册资料页的 `Under 18` 不可绕过弹窗和文案。
- 弹窗不可点击遮罩关闭。
- 只能点击 `Go back` 返回编辑页。
- `4000105` 返回后不再发起确认请求。

### 18 至 65 岁

- 正常显示 `Save changes`。
- 点击后调用 `/user/update`。

### 超过 65 岁

- 首次保存不携带 `age_confirm`，也不根据客户端年龄主动进入高龄确认状态。
- 只有服务端返回 `4000106` 后才展示 Figma黄色健康风险提示，并将主按钮改为 `Continue anyway`。
- 用户再次点击 `Continue anyway` 时，同一份资料的请求携带 `age_confirm: 1`。
- 修改生日、离开编辑页、提交成功，或服务端返回的不是 `4000106` 时清除高龄确认状态，后续请求重新不携带 `age_confirm`。

## 6. 更新用户资料

```http
POST /api/v1/app/user/update
Authorization: Bearer <access_token>
Content-Type: application/json
```

请求 Body：

```json
{
  "full_name": "Diana",
  "birth_day": "1990-01-01",
  "gender": 2
}
```

- Email 不提交。
- `age_confirm` 默认不提交；只有同一生日资料提交返回 `4000106` 后，用户再次点击 `Continue anyway` 时才提交 `age_confirm: 1`，不得提交 `0`。
- `4000105` 和 `4000106` 的页面处理、状态重置及服务端优先规则与首次完善资料完全一致。
- 两个年龄错误码统一引用网络层 `ApiBusinessCode`，Profile模块不得重复声明或直接写数字。
- 更新成功后直接使用响应 User 覆盖本地当前用户快照，不追加调用 `user/info`。
- 返回 Profile 后立即展示最新资料。
- 更新响应中的 `test_info` 和 `referral_card` 与其他用户字段一并解析、保存和刷新，不使用本地旧字段补全响应。
- 服务端返回的字段错误、业务错误和 Session 失效处理遵循登录注册需求文档。

## 9. Referral

- 标题使用 `referral_card.title`。
- 说明使用 `referral_card.description`。
- 按钮文字使用 `referral_card.button_text`。
- 点击按钮拉起系统分享面板；`share_text` 有效时分享“文案 + 空行 + `action_url`”，否则仅分享 `action_url`。
- `share_text` 非必填，缺失、`null`、类型错误或空字符串均不影响 Referral 卡片显示。
- `rewards_advocate` 和 `rewards_friend` 均为可选奖励结构，`reward_value` 支持整数或小数；缺失、为空或解析失败均不影响 Referral 卡片显示。
- Referral 曝光与点击均只上报一条事件，事件同时携带邀请人和被邀请人两组奖励字段。
- `referral_card` 缺失，或 `title`、`description`、`button_text`、`action_url` 任一必填字段为空时隐藏整张卡片；`action_url` 只校验非空，不校验协议和域名。
- `/user/info` 与 `/user/update` 均使用响应中的 `referral_card`，不保留响应之外的旧活动配置。
- exchange、`user/info` 或 `user/update` 任一处更新用户快照后，Home、Shop、Result 和 Profile 均使用同一份最新 Referral 数据。
- 用户取消分享不展示提示；系统分享调用失败时保留当前页面并展示 Toast。

## 10. Sign out

- 点击 `Sign out` 后不显示确认弹窗。
- 调用 `POST /api/v1/app/auth/logout` 并显示页面级 Loading。
- 请求期间禁止重复点击其他账号操作。
- 无论服务端退出成功、Session 已失效或网络失败，都清除本地 Token 和当前 User 快照。
- 保留当前 userId 对应的 Welcome 完成状态。
- 本地清理完成后无动画进入登录注册入口页。
- 详细错误和 Session 规则遵循登录注册需求文档。

## 11. Delete account

- 点击后展示不可逆确认弹窗。
- 标题：`Delete account?`
- 内容：`This will permanently deactivate your Nalo account and sign you out. This action cannot be undone.`
- 操作：`Cancel` / `Delete account`。
- 用户取消时不请求接口、不修改本地状态。
- 用户确认后调用 `POST /api/v1/app/auth/deactivate`，显示页面级 Loading 并禁止重复操作。
- 只有服务端返回成功时才清除 Token、当前 User 快照、当前 userId 对应的 Welcome 状态和 Analytics 用户身份。
- 注销成功不展示 Toast，无动画进入登录注册入口页。
- 注销失败时保留登录态和本地数据，并使用 Toast 展示服务端 `msg`。

## 12. 异常与边界 Case

- 进入 Profile 时 `user/info` 请求失败、超时或 Session 失效。
- `test_info` 或 `sum_count` 缺失、为 `null`、类型错误或负数。
- Name、Email、Birthday 或 Gender 缺失或格式异常。
- Profile 后台刷新期间用户点击 Edit、Sign out 或 Delete account。
- 用户编辑后没有修改任何字段仍点击保存。
- Name 只有空格、超长或包含多语言字符。
- 生日为今天、18 岁临界日、65 岁临界日、闰年生日或未来日期。
- 服务端和客户端年龄判断不一致时，以服务端结果为准。
- 更新资料请求超时但服务端可能已经成功。
- 更新成功响应缺少 User 或 User 字段格式错误。
- Shopify 管理 URL 未配置、非法或无法打开。
- 系统 Referral 分享面板无法拉起。
- Sign out 或 Delete account 请求期间 App 进入后台。
- 多次快速点击账号操作导致并发请求。
