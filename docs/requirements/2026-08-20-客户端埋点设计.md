# Nalo 客户端埋点设计

## 1. 文档定位

本文统一维护 Nalo Flutter 客户端的埋点规范、事件定义、属性定义、触发时机和实现职责。后续新增或修改任何客户端埋点，都在本文对应业务模块中维护。

本文是客户端埋点名称、属性类型、枚举值和触发规则的第一准则。代码实现与本文不一致时，应先确认需求并同步更新本文。

当前包含：

- 全局页面访问。
- 登录注册与 Onboarding。
- Home / Shop Tab 页面访问。
- 首页检测入口、检测结果曝光、通知、Referral 和 Profile 交互。
- 版本更新弹窗曝光与点击。
- Shop 商品曝光与点击。
- 客户端公共事件属性。
- Amplitude 用户属性与身份生命周期。

当前埋点版本统一为 `v1.0.0`。

## 2. 命名与数据规范

### 2.1 命名规范

- 事件名、事件属性名和用户属性名统一使用 `snake_case`。
- 页面名称统一由 Page Name 枚举维护。
- 事件名和属性名不得在页面中直接编写字符串。
- 同一属性在所有事件中保持相同数据类型。

### 2.2 通用取值

| 数据类型 | 否/失败/关闭 | 是/成功/开启 |
|---|---|---|
| Int | `0` | `1` |
| String | `"0"` | `"1"` |

- `is_success` 使用 Int。
- 通知状态使用 String。
- String 属性无值时传空字符串 `""`，另有明确规则的除外。
- 可选 Int 属性无值时不传，解析失败按事件规则传 `-1`。

### 2.3 事件版本

每个事件和属性均需记录首次使用版本。修改含义或数据类型时不得静默复用旧定义，应先评估是否新增事件或属性。

## 3. Amplitude 项目与运行配置

### 3.1 环境隔离

Test 和 Production 使用不同的 Amplitude Project/API Key：

| 环境 | 配置枚举 | 数据目标 |
|---|---|---|
| Test | `AppEnvironment.test` | Amplitude Test Project |
| Production | `AppEnvironment.production` | Amplitude Production Project |

环境通过 `lib/app/config/app_environment.dart` 手动切换，API Key 由 `lib/core/analytics/amplitude_config.dart` 提供。

项目通过 API Key 隔离，不依赖 iOS Bundle ID 或 Android Application ID，因此公共事件属性不增加 `app_environment`。

### 3.2 SDK 配置

- Amplitude 在应用生命周期中只初始化一次。
- `minIdLength = 1`，支持服务端短数字用户 ID。
- Debug 构建使用 `LogLevel.debug`。
- Profile / Release 构建使用 `LogLevel.warn`。
- 埋点异常只记录 Logger，不得中断业务请求或页面跳转。

## 5. 全局页面访问事件

### 5.1 `page_view`

| 事件名 | 版本 | 触发时机 | 属性名 | 类型 | 规则 | 端 |
|---|---|---|---|---|---|---|
| `page_view` | v1.0.0 | 已定义页面每次进入或返回重新可见 | `page_name` | String | 当前 Page Name 枚举值 | 客户端 |
| `page_view` | v1.0.0 | 已定义页面每次进入或返回重新可见 | `previous_page` | String | 上一个 Page Name；没有时为 `""` | 客户端 |

通用规则：

- 路由页面首次进入时上报。
- 从下一级路由返回后，当前页面重新可见时再次上报。
- 路由页面由 `AnalyticsNavigatorObserver` 统一处理。
- Tab 页面由主容器根据选中状态处理，不能依赖路由观察器。

### 5.2 Home / Shop Tab 规则

| 操作 | `page_name` | `previous_page` |
|---|---|---|
| Home 切换到 Shop | `tab_shop` | `tab_home` |
| Shop 切换到 Home | `tab_home` | `tab_shop` |
| Welcome 首次进入 Home | `tab_home` | `welcome` |
| 登录结果直接进入 Shop | `tab_shop` | `login_sign_in` |
| Home 进入检测流程 | `test_flow` | `tab_home` |
| Shop 进入检测流程 | `test_flow` | `tab_shop` |
| 检测流程返回 Home / Shop | 当前 Tab Page Name | `test_flow` |
| Home 进入检测历史 | `test_history` | `tab_home` |
| 检测历史返回 Home | `tab_home` | `test_history` |
| Home / Shop 进入个人中心 | `profile` | 当前 Tab Page Name |
| 个人中心返回 Home / Shop | 当前 Tab Page Name | `profile` |

首页和 Shop 为持久 Tab；检测流程、检测历史和个人中心是 Flutter 子页面。子页面返回后，当前 Tab 重新可见并再次上报 `page_view`。

### 5.3 曝光事件统一生命周期

所有曝光类事件统一按“页面可见周期”管理，包括 `page_view`、`test_result_section_view`、`test_result_item_view`、`test_history_entry_view`、`notification_enable_view`、`referral_view` 和 `sku_view`。

开启新曝光周期：

- 页面首次进入并实际可见。
- 从另一个 Flutter 页面返回，原页面重新可见。
- Tab 离开后重新进入。
- 页面被替换后重新进入。

同一曝光周期内不重新开始：

- 同一页面内部滚动，Item 滚出后再次滚入。
- 下拉刷新或分页加载。
- Riverpod 状态变化导致 Widget 重建。
- 普通弹窗显示和关闭。
- App 进入后台再回到前台。
- 跳转外部 Shopify 或其他外部应用后回到 App。

Item 曝光在每个页面可见周期内按业务唯一键去重。页面重新可见时清空上一周期的 Item 曝光集合；App 生命周期和外部应用返回不清空。

| v1.0.0 | `app_version` | String | 每次事件上报 | 当前 App 版本 | 客户端 |
| v1.0.0 | `os_version` | String | 每次事件上报 | 当前系统版本 | 客户端 |

|---|---|---|
| `page_name` | String | 点击时实际所在页面，首页为 `tab_home`，Shop 为 `tab_shop` |

### 9.3 `test_result_section_view`

| 属性名 | 类型 | 规则 |
|---|---|---|
| `page_name` | String | 事件触发时实际所在页面；首页为 `tab_home` |
| `detection_type` | String | `"1"` 皮质醇；`"2"` 睾酮；未知类型传 `""` |
| `item_count` | Int | 当前 Section 实际包含的结果数量 |
| `date` | String | 可选；仅 Test History 使用，首页不传 |
| `position` | Int | Section 在当前页面的实际展示位置，从 `1` 开始 |

皮质醇和睾酮是两个独立 Section，分别上报。空 Section 不展示也不上报。首页 `position` 按实际显示的 Section 顺序计算：皮质醇和睾酮都展示时分别为 `1`、`2`；只展示睾酮时，睾酮为 `1`。首页不传 `date`。

Section 曝光去重键：

```text
page_name + detection_type
```

### 9.4 `test_result_item_view`

| 属性名 | 类型 | 规则 |
|---|---|---|
| `page_name` | String | 事件触发时实际所在页面；首页为 `tab_home` |
| `test_id` | String | 服务端检测记录 `id` 转为 String |
| `detection_type` | String | `"1"` 皮质醇；`"2"` 睾酮；未知类型传 `""` |
| `position` | Int | 当前检测类型 Section 内的位置，从 `1` 开始 |
| `date` | String | 服务端返回的检测日期；无值传 `""` |
| `time_period` | String | 服务端返回的检测时段；无值传 `""` |
| `value` | String | 服务端返回的检测值；无值传 `""` |
| `unit` | String | 服务端返回的检测单位；无值传 `""` |
| `typical_range` | String | 服务端返回的典型范围；无值传 `""` |

皮质醇和睾酮的 `position` 分别从 `1` 开始。Item 曝光去重键：

```text
page_name + detection_type + test_id
```

首页和检测历史页都接入该事件；检测历史页的 `test_id` 使用服务端 `id` 转 String。`value`、`unit` 和 `typical_range` 属于用户健康数据，上报和后续使用必须符合隐私政策及 Amplitude 数据管理要求。

### 9.5 检测结果曝光规则

- Section 和 Item 都在 `visibleFraction >= 0.1` 时上报。
- Section 与 Item 独立上报，不要求 Amplitude 严格按 Section 在前、Item 在后的顺序接收。
- 同一页面可见周期内，已曝光的 Section 和 Item 不重复上报。
- 页面内滚出再滚入、接口刷新和 Widget 重建不重复上报。
- 刷新后新增且从未曝光的 `test_id` 达到条件时，正常首次上报。
- Home 首次进入、Shop 切换回 Home，以及 Test Flow、Test History、Profile 返回 Home 时开启新曝光周期。
- App 前后台切换或外部应用返回不创建新曝光周期。

### 9.6 首页入口事件

#### `test_history_entry_view` / `test_history_entry_click`

| 属性名 | 类型 | 规则 |
|---|---|---|
| `page_name` | String | 固定 `tab_home` |
| `total_test_count` | Int | 首页显示的历史检测总数；无法获取传 `-1` |

`test_history_entry_view` 在首页 Test history 卡片达到 10% 可见时上报。`test_history_entry_click` 在点击时立即上报，再进入 `test_history` 页面。

### 9.7 Test History 页事件

#### `test_history_filter_click`

| 属性名 | 类型 | 规则 |
|---|---|---|
| `page_name` | String | 固定 `test_history` |
| `detection_type` | String | All `""`；皮质醇 `"1"`；睾酮 `"2"` |
| `item_count` | Int | 被选筛选项的检测总数 |

点击筛选按钮时立即上报，再切换服务端筛选结果。

#### 历史结果 Section 和 Item

- 复用 `test_result_section_view` 和 `test_result_item_view`，`page_name` 固定为 `test_history`。
- Section 对应页面的月份分组；`date` 传服务端 `month_label`，`position` 按当前实际展示位置从 `1` 开始。
- Section 中只有一种检测类型时传对应 `detection_type`；同时包含多种类型时传 `""`。
- Item 的 `test_id` 使用服务端 `id` 转 String，其余字段使用服务端原始值。
- Section 和 Item 都在 `visibleFraction >= 0.1` 时上报。
- Section 去重键：`page_name + detection_type + date`。
- Item 去重键：`page_name + detection_type + test_id`。
- 同一页面访问周期内，滚出再滚入、下拉刷新、加载更多及 Widget 重建都不重复上报；新增数据达到曝光条件后正常上报。
- 退出后重新进入 Test History 开启新曝光周期；App 前后台切换不开启新周期。

## 10. Shop 商品事件

### 10.1 事件总览

| 事件名 | 页面 | 触发时机 | 版本 | 端 |
|---|---|---|---|---|
| `sku_view` | `tab_shop` | 商品首次达到可视曝光条件 | v1.0.0 | 客户端 |

### 10.2 SKU 公共业务属性

`sku_view` 和 `sku_click` 使用相同的商品属性：

| 属性名 | 类型 | 规则 |
|---|---|---|
| `page_name` | String | 固定 `tab_shop` |
| `product_id` | String | 商品 ID；客户端将模型 Int 转为 String |
| `variant_id` | String | 商品规格 ID；客户端将模型 Int 转为 String |
| `title` | String | 商品标题；为空传 `""` |
| `description` | String | 商品描述；为空传 `""` |
| `image_url` | String | 商品大图 URL；为空传 `""` |
| `price` | Int | 现价，单位美分；解析失败传 `-1` |
| `compare_at_price` | Int | 划线原价，单位美分；无原价不传；有值但解析失败传 `-1` |
| `currency` | String | ISO 4217 币种代码，例如 `USD`、`CNY`；为空传 `""` |

金额转换示例：

```text
"29.99" → 2999
"29" → 2900
无法解析 price → -1
compare_at_price 为 null → 不传
compare_at_price 有值但无法解析 → -1
```

`description` 是商品描述。旧表中“0 普通商品、1 订阅商品”属于字段说明错位，本版本不增加商品订阅类型属性。

### 10.3 `sku_view` 曝光规则

- 使用 `visibility_detector` 获取商品卡片可视比例。
- 当 `visibleFraction >= 0.1` 时满足曝光条件。
- 同一次进入 Shop Tab 期间，同一 `product_id + variant_id` 只上报一次。
- 商品滚出屏幕后再次滚回，在同一次 Shop 停留中不重复上报。
- 离开 Shop Tab 后清空本轮曝光集合；再次进入 Shop 时允许重新上报。
- 从 Profile 等 Flutter 子页面返回 Shop 后开启新曝光周期，当前可见商品允许重新上报。
- App 前后台切换或从外部 Shopify 返回不创建新曝光周期，不重新上报。
- 分页加载的新商品在达到可视比例后正常上报。
- 下拉刷新后，同一次 Shop 停留中已曝光的相同 `product_id + variant_id` 不重复上报。
- 只有实际商品卡片参与曝光，Loading、空态、错误态和 Referral 卡片不参与。

### 10.4 `sku_click` 点击规则

- 当前触发入口为商品卡片的 Get kit 按钮。
- 点击时立即上报，不等待 Shopify 购买链接请求。
- 购买链接请求成功或失败不改变本次点击是否成立。
- 按钮处于 Loading/Disabled 状态时不可重复点击，不重复上报。

### 10.5 `shop_shopify_url_request` 请求结果

用于记录 Shopify 跳转链接请求结果，不表示外部浏览器是否成功打开。

| 属性名 | 类型 | 成功规则 | 失败规则 |
|---|---|---|---|
| `product_id` | String | 当前商品 ID | 当前商品 ID |
| `variant_id` | String | 当前规格 ID | 当前规格 ID |
| `url` | String | 原样上报完整 Shopify URL，包括 Query 和 Fragment | `""` |
| `is_success` | Int | `1` | `0` |
| `fail_reason` | String | `""` | `code: reason` |

触发规则：

- `sku_click` 先上报，再发起 Shopify URL 请求。
- 请求返回且 URL 格式、HTTPS 和有效期校验完成后，上报请求结果。
- 服务端成功且链接校验通过：`url` 原样上报、`is_success = 1`、`fail_reason = ""`。
- 请求或链接校验失败：`url = ""`、`is_success = 0`，并上报稳定失败原因。
- 重复请求保护导致网络请求未实际发出时，不上报该事件。
- URL 请求成功后，即使 `launchUrl()` 打开外部浏览器失败，本事件仍为成功。
- 本事件不额外传 `page_name`，但自动携带所有公共事件属性。

失败原因规则：

```text
ApiException        → 服务端 code: 服务端 reason
NetworkException    → 网络类型: reason
SessionExpired      → session_expired: reason
ResponseFormat      → response_format_error: reason
Unknown             → unknown_error: reason
```

## 12. 用户身份生命周期

### 12.1 登录成功

```text
取得服务端 user_id
→ Amplitude setUserId
→ 设置 user_id、login_status、notification_permission、kc_id
→ iOS ATT 状态确定后设置 x-idfa
→ 上报 login_request_result 成功
```

未登录时，公共事件属性 `user_id` 使用空字符串。

### 12.2 退出、失效与注销

- 主动退出：业务会话清理后调用 `resetIdentity()`。
- Token 失效：业务会话清理后调用 `resetIdentity()`。
- 注销账号：后端注销成功后调用 `resetIdentity()`。
- Amplitude `reset()` 会生成新的 Amplitude 匿名身份。
- `reset()` 不删除钥匙串中的自有 `kc_id`。
- 当前项目尚无账号注销接口，后续接入时复用 `resetIdentity()`。

### 12.3 ATT / IDFA

```text
AuthEntryPage 首次展示完成
→ 查询 ATT 状态
→ 尚未决定时请求 ATT
→ 已授权：读取真实 IDFA
→ 拒绝/受限：使用全 0 IDFA
→ 设置 Amplitude 用户属性 x-idfa
```

iOS `Info.plist` 已配置 `NSUserTrackingUsageDescription`。Android 不设置 IDFA 用户属性。

## 13. Flutter 实现职责

### 13.1 调用流转

```text
Widget / ViewModel / NavigatorObserver / Tab 容器
→ AnalyticsService
→ 公共属性采集
→ Amplitude SDK
```

- Widget 上报点击和可视曝光。
- ViewModel 上报网络请求和业务结果。
- `AnalyticsNavigatorObserver` 上报路由页面曝光与返回曝光。
- `HomePage` 根据 Tab 切换上报 `tab_home` / `tab_shop` 页面访问。
- `AnalyticsService` 转换枚举、补充公共属性并隔离 Amplitude SDK。
- 普通 Dart 类通过构造函数注入 `AnalyticsService`，不读取全局 Provider。

### 13.2 核心类型职责

第一版事件和属性继续统一维护在 `lib/core/analytics/analytics.dart`：

| 类型 | 职责 |
|---|---|
| `AnalyticsEvent` | 维护事件名称 |
| `AnalyticsPageName` | 维护 Page Name 枚举 |
| `AnalyticsEventProperty` | 维护业务事件属性名 |
| `AnalyticsCommonProperty` | 维护自动添加的公共事件属性名 |
| `AnalyticsUserProperty` | 维护 Amplitude 用户属性名 |
| `AnalyticsLoginClickMethod` | 维护登录入口枚举 |
| `AnalyticsLoginMethod` | 维护登录方式枚举 |
| `AnalyticsGender` | 维护 Gender 枚举 |
| `AnalyticsService` | 对业务层暴露统一上报和身份接口 |
| `AmplitudeAnalyticsService` | 调用 Amplitude SDK |
| `analyticsProvider` | 通过 Riverpod 注入 Analytics Service |
| `AnalyticsWidgetRef` | 为 Widget 提供简短调用入口 |
| `AnalyticsNavigatorObserver` | 上报路由 Page View |

Shop 实施时补充：

| 类型/依赖 | 职责 |
|---|---|
| SKU 属性构造方法 | 统一转换商品字段和美分金额 |
| Shop 曝光周期 | Tab 重新进入或 Flutter 子页面返回时递增 |

首页埋点实施时补充：

| 类型/依赖 | 职责 |
|---|---|
| 首页曝光周期 | Home 首次进入、Tab 重新进入或 Flutter 子页面返回时递增 |

| Item 曝光集合 | 按 `page_name + detection_type + test_id` 管理单次可见周期去重 |

## 16. 维护要求

- 新增埋点前先在本文增加事件、属性、类型、枚举值和触发时机。
- 修改事件含义、字段类型、数据流转或生命周期时，同步更新本文。
- 删除或废弃事件时，从代码和本文同时删除，并记录替代方案或删除原因。
- 事件实现应复用统一枚举和属性构造方法。
- 公共事件属性只能由 `AnalyticsService` 生成。
- 埋点失败不得阻断主要业务流程。
