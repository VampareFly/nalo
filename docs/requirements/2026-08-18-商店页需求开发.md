# 商店页业务逻辑需求

## 基本信息

- 日期：2026-08-18
- 当前状态：商品列表、分页和购买 URL 已完成 Flutter 基础接入，待服务端联调
- 设计来源：[Nalo v1.5 Shop Figma](https://www.figma.com/design/RXZsVLSYDkFqaHZtHzLX1G/Nalo-v1.5-08.16.2026?node-id=1-108&t=zHf6pH2mbEandaUh-0)
- Figma 节点：Shop 页面 `1:108`
- 文档范围：只记录商品数据、列表状态、购买跳转和分层职责，不记录颜色、字体、间距、圆角等 UI 还原要求
- 架构：Flutter + Riverpod + MVVM，调用方向为 View → ViewModel/Provider → Repository → Service → Nalo 服务端 → Shopify

## 目标

将商店页当前的本地静态商品数据和写死的 Shopify 预览链接替换为服务端数据。

商品列表由 Nalo 服务端返回；用户点击购买时，客户端携带商品 ID 和规格 ID 请求临时跳转地址，成功后使用系统外部浏览器打开 Shopify 页面。

Widget 只消费页面状态和派发事件，不直接请求接口、解析 JSON 或拼接 Shopify URL。

## 页面数据流

```text
ShopPage
  ↓ watch / dispatch
ShopViewModel / ShopProvider
  ↓
ShopRepository
  ↓
ShopService
  ↓
Nalo 服务端
  ├─ GET  /api/v1/app/products
  └─ POST /api/v1/app/products/shopify-url → Shopify 商品页
```

## 1. 商品列表

### 请求

```http
GET /api/v1/app/products
Authorization: Bearer <access_token>
```

| 参数 | 类型 | 必填 | 默认值 | 示例 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `page` | int | 否 | `1` | `1` | 分页页数 |
| `page_size` | int | 否 | `10` | `10` | 每页数量 |
| `detection_type` | string | 否 | 全部 | `cortisol` | 激素类型 |

`detection_type` 可选值：

| 值 | 含义 |
| --- | --- |
| `cortisol` | 皮质醇，压力激素 |
| `testosterone` | 睪酮，雄性激素 |

- 展示全部商品时不传 `detection_type`。
- 客户端不自行根据标题或描述推断激素类型。
- 页面不暴露类型筛选入口，默认不传 `detection_type` 并请求全部商品。

### 完整成功响应

```json
{
  "code": 0,
  "msg": "success",
  "reason": "",
  "trace_id": "e2b6b52f-0a4f-4d9f-aef4-d0a3a23332e0",
  "data": {
    "products": [
      {
        "product_id": 7748959535217,
        "variant_id": 43593329311857,
        "title": "Gift Card",
        "description": "This is a gift card for the store",
        "image_url": "https://cdn.shopify.com/s/files/1/0693/3010/8529/files/gift_card.png?v=1783060451",
        "price": "10.00",
        "compare_at_price": null,
        "currency": "USD"
      }
    ],
    "pagination": {
      "page": 1,
      "page_size": 5,
      "total": 19,
      "has_more": true
    }
  }
}
```

- `data.products` 为当前页商品数组。
- `data.pagination.page` 为服务端实际返回的当前页。
- `data.pagination.page_size` 为当前页分页数量。
- `data.pagination.total` 为符合当前查询条件的商品总数。
- `data.pagination.has_more` 为 `bool`：`true` 表示还有下一页，`false` 表示已加载到最后一页。
- `reason` 和 `trace_id` 属于通用响应字段，Shop 业务模型不解析。

### 返回字段

| 字段 | 类型 | 可空 | 示例 | 说明 |
| --- | --- | --- | --- | --- |
| `product_id` | int | 否 | `7748959535217` | Shopify 商品 ID，对应 `product.id` |
| `variant_id` | int | 否 | `43593329311857` | 默认规格 ID，对应 `variants[0].id` |
| `title` | string | 否 | `Cortisol Test Kit` | 商品标题 |
| `description` | string | 是 | `3 saliva strips per cycle...` | `body_html` 去标签后的纯文本 |
| `image_url` | string | 是 | `https://cdn.shopify.com/...` | 商品主图地址 |
| `price` | string | 否 | `20.00` | 默认规格现价 |
| `compare_at_price` | string | 是 | `25.00` | 默认规格原价，无则返回 `null` |
| `currency` | string | 否 | `USD` | ISO 货币代码，例如 `USD`、`CNY` |

### 展示规则

- 商品卡片按服务端返回顺序展示，客户端不二次排序。
- `title`、`description`、`image_url`、`price`、`currency` 均使用接口数据，不再在 Widget 或 Provider 中写死。
- `description == null` 时隐藏商品描述区域，不展示空字符串占位。
- `image_url == null` 时展示项目统一商品占位内容。
- `compare_at_price != null` 时展示原价；为 `null` 时隐藏原价区域。
- 价格按 `currency` 格式化，不固定拼接美元符号。具体货币格式化规则待与服务端及产品确认。
- `image_url` 加载失败时展示项目统一占位内容，不影响标题、价格和购买操作。
- 描述为服务端处理后的纯文本，Flutter 不再解析 Shopify HTML。

## 2. 列表加载与分页

- 首次进入 Shop Tab 时请求第 `1` 页，`page_size` 使用 `10`。
- 首次加载期间展示页面加载状态，并防止重复请求。
- 首次加载失败时展示可重试错误状态。
- 已有商品数据后加载更多失败，保留当前列表并提供重试，不清空已有数据。
- 空列表展示 Shop 空状态，不使用错误页代替。
- 页面支持下拉刷新：重新请求第 `1` 页，成功后替换当前列表并重置分页状态。
- 页面支持上拉加载：只有 `has_more == true` 且当前没有加载任务时才请求下一页。
- 上拉加载成功后追加新商品，并使用响应 `pagination` 中的 `page` 和 `has_more` 覆盖当前分页状态。
- `pagination.has_more == false` 时停止触发上拉加载，不再请求后续页。
- 下拉刷新和上拉加载不能并发，后触发的操作需等待当前列表请求完成。

## 3. 生成 Shopify 购买链接

### 请求

```http
POST /api/v1/app/products/shopify-url
Authorization: Bearer <access_token>
Content-Type: application/json
```

```json
{
  "product_id": 7748959535217,
  "variant_id": 43593329311857
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `product_id` | int | 是 | 列表接口返回的 Shopify 商品 ID |
| `variant_id` | int | 是 | 列表接口返回的默认规格 ID |

### 返回

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `product_url` | string | 是 | 带有服务端签名或归因信息的 Shopify 商品链接 |
| `expires_at` | int | 是 | 链接签名过期时间，Unix 秒级时间戳 |

### 点击与跳转规则

1. 用户点击某个商品的购买按钮。
2. ViewModel 使用该商品的 `product_id` 和 `variant_id` 请求购买链接。
3. 请求期间只禁用当前商品的购买按钮，并展示轻量 Loading。
4. 请成功后校验 `product_url` 为合法 HTTPS URL，然后使用系统外部浏览器打开。
5. 链接请求失败、字段异常或外部浏览器无法打开时，停留当前页并展示可理解的错误提示。
6. 请求成功、失败或用户返回 App 后，当前按钮必须恢复可用状态。

客户端不缓存或复用 `product_url`。每次购买都重新请求，避免使用过期签名或错误的用户归因信息。

本模块和其他业务接口中的时间戳统一按 Unix 秒级处理；Flutter 转换为 `DateTime` 时需先转为毫秒。

## 4. 购买并发与防重复

- 同一商品的购买链接正在生成时，忽略后续重复点击。
- 不同商品的按钮状态独立，但页面同一时间只允许发起一次外部购买跳转，避免连续打开多个浏览器页面。
- 客户端不预测、修改或拼接服务端返回的 URL 查询参数。
- `product_id`、`variant_id`、`product_url` 和签名参数不写入 Toast；URL 记录日志时必须移除 Query 或整体脱敏。

## 5. 页面状态建议

- `isInitialLoading`：首次加载商品。
- `products`：已加载的商品列表。
- `currentPage`：当前已加载页数。
- `hasMore`：是否存在下一页，直接使用响应 `pagination.has_more`。
- `selectedDetectionType`：当前类型筛选，当前默认全部。
- `loadingProductId`：当前正在生成购买链接的商品 ID。
- `initialError`：首次加载错误。
- `loadMoreError`：加载更多错误。
- `purchaseError`：购买链接生成或外部打开错误。

## 6. 分层职责

### View

- 展示页面状态和商品数据。
- 派发加载、重试、筛选和购买事件。
- 根据 `loadingProductId` 更新对应按钮状态。
- 不直接调用 Dio、解析响应或持有静态 Shopify URL。

### ViewModel / Provider

- 管理商品列表、分页、筛选、加载和错误状态。
- 调用 Repository 获取商品和临时购买链接。
- 防止重复加载和重复购买请求。
- 不解析 JSON，不直接依赖 Dio。

### Repository

- 编排 ShopService 的列表与购买链接请求。
- 将 Service DTO 转换为页面使用的商品 Model。
- 屏蔽服务端响应包和数据来源差异。

### Service

- 通过项目现有 ApiClient 请求两个 Shop 接口。
- 序列化查询参数和购买请求 Body。
- 解析并校验 DTO 必填字段，将格式错误交给统一网络层处理。
- 不操作 Widget、Toast 或路由。

### 外部跳转

- 使用项目现有 `url_launcher` 打开服务端返回的 HTTPS URL。
- 外部浏览器调用由页面交互层执行，URL 获取和业务状态仍由 ViewModel 管理。

## 7. 通用响应与错误处理

- 两个接口均遵循项目统一响应包 `{code, msg, reason, trace_id, data}`。商品列表的 `data` 包含 `products` 和 `pagination`。
- HTTP 非 2xx、业务 `code != 0`、超时、无网络、字段缺失和类型错误分别交给现有网络层映射。
- 登录失效类业务码继续使用项目全局 Session 处理，Shop ViewModel 不重复清理 Token 或跳转登录页。
- 当前接口未提供 Shop 专用业务错误码，未知错误展示服务端消息或统一可重试文案，并保留当前页面数据。

## 11. 逻辑完成标准

- Shop 页商品来自 `GET /api/v1/app/products`，不使用本地写死数据。
- 商品标题、描述、图片、现价、原价和币种能根据服务端响应正确展示。
- `compare_at_price` 为 `null` 时不展示原价。
- 用户点击购买时，客户端使用当前商品的 `product_id` 和 `variant_id` 请求临时 URL。
- 客户端不再保存或拼接固定 Shopify 商品 URL。
- 重复点击不会重复请求或打开多个外部页面。
- 列表加载、空数据、错误和重试都有明确状态。
- 下拉刷新会重置列表，上拉加载会追加商品，`has_more == false` 后不再请求下一页。
- 网络请求、JSON 解析、分页编排和购买链接获取不写在 Widget 中。
- 签名 URL 和可能的归因参数不会出现在日志或 Toast 中。
