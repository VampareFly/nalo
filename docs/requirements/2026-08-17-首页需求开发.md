# 首页业务逻辑需求

## 基本信息

- 日期：2026-08-17
- 当前状态：新版 UI 与接口前占位逻辑已实现，服务端协议和未决跳转待接入
- 设计来源：[Nalo v1.5 首页 Figma](https://www.figma.com/design/RXZsVLSYDkFqaHZtHzLX1G/Nalo-v1.5-08.16.2026?node-id=22-3343&t=zHf6pH2mbEandaUh-0)
- Figma 节点：首页内容 `22:3343`，完整页面与底部导航 `22:3338`
- 文档范围：只记录首页数据、状态、权限、跳转和业务规则，不记录颜色、字体、间距、圆角等 UI 还原要求
- 架构：Flutter + Riverpod + MVVM，调用方向为 View → ViewModel/Provider → Repository → Service → Nalo 服务端

## 目标

重建登录后的首页业务结构，提供检测入口、通知提醒、检测历史、最近结果、邀请好友和底部 Tab 导航。

首页 Widget 只消费状态和派发事件，不直接请求接口、解析响应或计算服务端业务状态。

## 页面数据流

```text
HomePage
  ↓ watch / dispatch
HomeViewModel / HomeProvider
  ├─ HomeRepository → HomeService → Nalo 服务端
  └─ NotificationPermissionService → 系统通知权限
```

首页优先使用聚合接口一次返回所需数据。如果服务端拆分为多个接口，由 Repository 并发聚合为单一首页状态，避免多个 Widget 各自请求。

## 1. 首页初始化

- 登录成功进入首页或冷启动恢复 Session 后加载首页数据。
- 首次加载期间禁止重复发起相同请求。
- 加载成功后统一更新首页状态。
- 刷新失败时优先保留已有数据；没有可用数据时展示可重试错误状态。
- App 从后台恢复时只刷新通知权限；首页业务数据是否刷新由后续缓存和接口策略确定。

## 2. 问候与用户名首字符

- 问候语由服务端返回，客户端不根据本地时间自行生成。
- 服务端问候语接口和字段尚未定义。
- 用户名来自当前用户信息。
- 问候语下方展示去除首尾空格后的完整用户名。
- 顶部头像展示用户名的第一个可见字符；英文展示首字母，中文展示第一个汉字。
- 头像取值时需要按 Unicode 字符处理，不能直接按 UTF-16 code unit 截断复合字符。
- 用户名为空、仅包含空格或读取失败时的兜底内容待确认。

## 3. 发起检测

- 用户点击首页检测入口后进入现有 `TestFlowPage`。
- 连续点击只触发一次页面跳转。
- 相机权限、试纸扫描和检测流程前置条件由 Test Flow 模块处理，首页不重复实现。

## 4. 通知提醒权限

### 展示规则

- 通知权限未开启时展示提醒入口。
- 通知权限已授权或临时授权时隐藏。
- 权限读取完成前不展示入口，避免页面闪现。
- 页面首次进入和 App 从后台恢复时重新读取权限。

### 点击规则

- 权限从未请求时，点击后发起系统通知授权。
- 权限已拒绝时，点击后打开 App 系统设置。
- 从系统设置返回后重新检查权限；已开启则隐藏，未开启则继续展示。
- 实际提醒创建、时间调度和服务端同步不属于首页职责。

## 5. 检测历史

- 检测总数来自服务端，不能写死。
- 数量为 `1` 时使用单数文案，其他数量使用复数文案。
- 点击历史入口进入完整 `TestHistoryPage`。
- 历史页支持 All、Cortisol、Testosterone 三种筛选，筛选项展示各自结果数量。
- 历史结果按月份分组，每个月份展示当前筛选条件下的结果数量。

## 6. 最近检测结果

### 数据范围

- Cortisol 和 Testosterone 分类型展示。
- 每条结果包含日期时间、检测时段、结果状态、参考范围和单位。
- 首页每个检测类型只展示服务端顺序中的最近 3 条，历史页展示完整结果。
- 客户端不得根据结果数值自行判定 Normal、Low 或 High，状态和对应语义由服务端提供。
- 日期按用户本地时区格式化。

### 列表规则

- 首页每种类型最多展示最近 3 条，完整数据在检测历史页展示。
- 每种类型的结果在各自区块内逐条向下排列。
- 不做横向轮播、分页或固定数量裁剪。
- 多条结果的排序规则尚未定义；协议明确前保持服务端返回顺序，客户端不二次排序。
- 某一类型没有任何结果时，隐藏该类型的整个区块。
- 两种类型都没有结果时，两个结果区块都隐藏。
- 加载失败或返回异常数据时的处理规则待接口协议和错误状态设计确认。

### 结果行交互

- “结果行”指单条包含日期、时段、状态和参考范围的记录。
- 结果行是否可以点击、是否进入单次结果详情页尚未确认。

## 7. 邀请好友

- 邀请活动是否展示、优惠比例和描述文案来自服务端活动配置。
- 活动关闭或服务端不返回活动时隐藏入口。
- 点击后进入独立邀请页面还是直接发起系统分享暂未确定。
- 当前首页已有的邀请码复制和外链逻辑不能直接迁移，需按最终交互重新接入。

## 8. 底部 Tab

- 首页继续作为 Home Tab 的内容页。
- 中间检测入口继续进入 `TestFlowPage`。
- Shop Tab 继续进入现有 `ShopPage`。
- Tab 切换时保留各 Tab 已有页面状态，避免重复创建和重复请求。
- 从其他流程指定进入 Shop 时，仍需要支持首页容器初始化到 Shop Tab。
- Home 和 Shop 是可选中的持久 Tab；中间 Scan 是操作入口，不作为持久选中页。
- 点击 Scan 始终进入 `TestFlowPage`，返回后保持进入前选中的 Home 或 Shop。
- 底部 Tab 的纯视觉调整不记录在本文档中。

## 9. 首页状态建议

- `isLoading`：首次加载状态。
- `greeting`：服务端问候语。
- `userName`：问候语下方展示的完整用户名。
- `userInitial`：用户名首字符或后续确认的兜底值。
- `totalTestCount`：历史检测总数。
- `cortisolResults`：Cortisol 完整结果列表。
- `testosteroneResults`：Testosterone 完整结果列表。
- `referralOffer`：邀请活动配置。
- `notificationPermission`：通知权限状态。
- `error`：页面级错误。

## 10. 分层职责

### View

- 根据 Provider 状态决定模块是否展示。
- 派发检测、权限、历史、邀请和 Tab 点击事件。
- 不直接访问网络或解析接口响应。

### ViewModel / Provider

- 管理首页加载、刷新和状态组合。
- 组合当前用户、首页业务数据和通知权限。
- 控制重复请求和重复跳转。

### Repository

- 统一获取首页数据。
- 根据后续协议处理缓存与多接口聚合。
- 将 Service DTO 转换为首页 Model。

### Service

- 发起首页网络请求。
- 解析通用响应包和字段类型。
- 将错误映射给 Repository，不直接操作 Widget。

## 11. 服务端待提供

- 问候语字段、接口位置和空值规则。
- 当前用户名字段及可空规则。
- 检测总数。
- Cortisol 和 Testosterone 完整结果及月份分组信息。
- 每条结果的日期时间、类型、状态、参考范围和单位。
- 结果列表的排序规则。
- Referral 活动展示状态、优惠信息和目标数据。
- 首页使用聚合接口还是多个独立接口。

## 12. 影响范围

### 业务逻辑替换

- 当前首页静态报告和趋势数据 Provider。
- 当前首页 Widget 内部的 Toast 占位跳转。
- 当前 Referral 静态邀请码和外链逻辑。
- 当前通知提醒入口与报告卡片的耦合。

### 新增

- 首页统一 ViewModel/Provider。
- 首页业务 Model。
- 首页 Repository 和 Service，具体文件随接口协议确定。
- 首页加载、错误和模块显隐规则。
- 最近结果列表数据规则。
- 底部 Tab 的 Home/Shop 状态保留与 Scan 独立入口逻辑。

### 保留

- `HomePage.path` 和现有首页路由入口。
- `TestFlowPage` 检测流程。
- 现有通知权限 Service 和 Provider。
- Shop 和 Profile 模块现有实现。

## 13. 依赖影响

- 业务逻辑预计不新增第三方依赖。
- 使用 Riverpod、GoRouter 和项目现有网络层实现。
- 如后续 UI 还原需要新增字体或资源，只在代码实施前单独确认，不写入本文档的业务需求。

## 14. 实施顺序

1. 获取首页接口协议。
2. 确认用户名空值规则、结果排序和结果行点击行为。
3. 建立首页 Model、Repository、Service 和 ViewModel/Provider。
4. 接入问候语和用户名首字符。
5. 接入检测入口和通知权限规则。
6. 接入检测总数和检测历史页面。
7. 接入两类最近结果及显隐规则。
8. 接入 Referral 活动配置和暂定交互。
9. 接入底部 Tab 最终逻辑。
10. 补充 Provider 单元测试和页面 Widget 测试。

## 15. 逻辑完成标准

- 首页数据通过 Provider 获取，不由 Widget 写死。
- 用户名首字符兼容英文、中文和 Unicode 复合字符。
- 检测入口只触发一次有效跳转。
- 通知入口根据权限状态正确展示、授权、跳转设置和刷新。
- 检测历史展示真实总数，并支持类型筛选和月份分组。
- 最近结果按类型和服务端顺序展示，无数据类型正确隐藏。
- Referral 仅在活动有效时展示。
- Tab 切换不会重复创建页面或重复请求。
- 网络、业务状态和权限逻辑不写在 Widget 中。
