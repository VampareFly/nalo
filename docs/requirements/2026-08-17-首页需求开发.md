## 目标

首页作为登录后的主入口，负责：

- 展示服务端问候语和当前用户名称。
- 进入试纸检测流程。
- 展示通知提醒入口。
- 展示 Cortisol 和 Testosterone 最近检测结果。
- 进入检测历史、Referral 和 Shop。
- 在部分接口失败时保留可继续使用的首页主体。

首页不负责试纸拍摄、分析、结果判断和保存，这些能力统一由 Test Flow 模块处理。

## 页面结构与入口

```text
HomePage
├─ HomeDashboard
│  ├─ 问候语与用户名
│  ├─ Scan your strip
│  ├─ 通知提醒
│  ├─ Test history
│  ├─ Cortisol 最近结果
│  ├─ Testosterone 最近结果
│  └─ Referral
└─ HomeBottomTabs
   ├─ Home
   ├─ Scan
   └─ Shop
```

## 1. 首页初始化

- 进入 `HomePage` 后通过 `homeDashboardProvider` 加载首页数据。
- Provider 同时依赖当前用户存储和首页 Repository。
- 首页数据通过一个聚合接口统一请求，不再分别请求两种检测类型。
- 接口完成前首页结果区域处于 Loading 状态，顶部栏保持展示。
- 接口失败不展示整页错误状态，首页主体仍可使用。
- 每次进入 Home Tab 时重新加载检测结果，包括首次进入、从子页面返回、从 Shop 切回 Home，以及 App 回前台时当前停留在 Home。
- 首页不支持下拉刷新。
- App 回到前台时同时刷新通知权限。

## 2. 问候语与用户名称

### 问候语

- 优先展示首页接口返回的 `greeting.message`。
- 不使用 `greeting.type` 在客户端重新生成服务端文案。
- 首页接口失败或 `greeting.message` 缺失时，客户端展示不带时间语义的通用文案 `Hello,`。

### 用户名称

- 用户名来自本地当前用户快照的 `full_name`。
- 问候语下方展示去除首尾空格后的完整用户名。
- 顶部头像展示用户名首字符，英文转换为大写，中文展示第一个汉字。
- 用户名为空或读取失败时，完整用户名展示 `Nalo`，头像展示 `N`。

## 3. 发起检测

- 点击首页 `Scan your strip` 进入 `TestFlowPage`。
- 点击底部中间 Scan 按钮同样进入 `TestFlowPage`。
- 检测类型选择、相机权限、试纸拍摄、服务端分析、确认和保存均遵循试纸检测流程文档。
- 首页不重复检查相机权限或检测流程前置状态。
- 从检测流程返回首页后立即刷新检测结果。

## 4. 通知提醒

### 展示规则

- 通知权限读取完成前不展示提醒卡片，避免闪现。
- 通知权限未开启时展示 `Turn on reminders`。
- 通知权限已开启时隐藏整个提醒卡片。

### 交互

- App 级权限 Provider 负责首次权限请求。
- 用户点击 Enable 后进入系统 App 设置页。
- App 从后台回到前台时重新读取通知权限。
- 用户已开启权限时自动隐藏提醒卡片。
- 具体提醒时间、通知调度和服务端同步不属于首页职责。

## 5. 最近检测结果

### 请求规则

- 使用 `GET /api/v1/app/index`。
- 接口不传请求参数，一次返回问候语、历史总数和两类最近检测结果。
- 首页使用独立的首页 Service、Repository 和响应模型，不复用 Test Flow 的检测结果接口模型。

### 字段映射

| 首页内容 | 接口字段 | 规则 |
| --- | --- | --- |
| 问候语 | `greeting.message` | 直接展示服务端原文 |
| 检测总数 | `history.total` | 展示为首页 `tests total`，不使用最近结果数量计算 |
| 模块类型 | `last_tests[].detection_type` | 使用外层类型划分 Cortisol 和 Testosterone 模块 |
| 日期 | `last_tests[].list[].date` | 直接展示 |
| 时段 | `last_tests[].list[].time_period` | 直接展示 |
| 检测值 | `last_tests[].list[].value` | 保留 `<`、`>` 等符号 |
| 单位 | `last_tests[].list[].unit` | 与 value 组合展示，不修改大小写 |
| 典型范围 | `last_tests[].list[].typical_range` | 直接展示，不在客户端重新计算 |

### 展示规则

- Cortisol 和 Testosterone 分成两个独立模块。
- 使用外层 `last_tests[].detection_type` 决定整个 `list` 所属模块；示例假数据中的内外层类型不一致暂不作为特殊业务处理。
- `list` 中的结果逐条向下展示，不在客户端限制最大数量。
- 保持服务端返回顺序，客户端不二次排序。
- 某类型不存在或对应 `list` 为空时，隐藏该类型模块。
- 首页接口失败或响应无法解析时，隐藏两个最近结果模块，历史总数按 `0` 展示，问候语使用客户端兜底。
- `history`、`history.total` 缺失或格式异常时，仅将检测总数降级为 `0`，不得影响 `greeting` 和 `last_tests` 的展示。
- 结果行不支持点击，也不进入单次结果详情页。

## 6. 检测历史

### 入口

- 点击首页 `Test history` 进入 `TestHistoryPage`。
- 每次进入历史页都请求第一页数据。
- 页面支持下拉刷新；刷新时重新请求当前筛选第一页并覆盖该筛选缓存。
- 单条历史结果不支持点击，也不进入详情页。

### 筛选

- 支持 All、Cortisol、Testosterone 三种筛选，默认选中 All。
- All 请求 `detection_type=all`，Cortisol 请求 `detection_type=cortisol`，Testosterone 请求 `detection_type=testosterone`。
- 首次切换到尚未加载的筛选时清空当前列表和分页状态，不传 `end_date`，请求第一页。
- 同一次页面浏览期间分别缓存三个筛选的数据和分页状态；已加载的筛选再次点击或切回时直接展示缓存，不重复请求。
- 离开历史页后筛选缓存随页面 Provider 释放，再次进入仍请求默认 All 第一页。
- 筛选由服务端完成，客户端不使用 All 数据自行过滤。
- 筛选按钮和结果摘要数量使用接口 `pagination` 中的服务端总数：

```json
"pagination": {
  "has_more": false,
  "next_end_date": "",
  "all": 5,
  "cortisol": 4,
  "testosterone": 1
}
```

- 每次筛选和分页响应都使用最新的 `pagination.all/cortisol/testosterone`。
- 筛选下方的结果数量使用当前筛选对应的总数。

### 月份分组与结果行

- 客户端保持服务端 `groups` 顺序，不重新计算月份和排序。
- 月份标题直接展示 `month_label`。
- `sort_key` 仅用于分页数据合并和识别相同月份，不作为页面文案。
- 月份右侧数量展示当前分组 `items.length`。
- 结果行展示 `date`、`time_period`、`detection_type`、`value + unit` 和 `typical_range`。
- Cortisol 和 Testosterone 使用各自的结果行类型标识。
- 服务端返回的值、单位和典型范围保持原文，不在客户端重新计算或修改大小写。

### 分页

- 首次请求、未缓存筛选的首次请求和下拉刷新时不传 `end_date`。
- 页面接近列表底部且 `has_more=true` 时请求下一页。
- 下一页将上一页返回的 `next_end_date` 作为 `end_date`。
- `has_more=false` 时停止分页。
- 分页请求进行中禁止重复请求相同页。
- 新页包含已有 `sort_key` 时，将 items 追加到已有月份；否则追加新的月份分组。
- 分页结果保持服务端顺序，客户端不二次排序。

### 加载、空状态与失败

- 首次请求期间展示页面 Loading。
- 首次请求成功但 `groups` 为空时展示历史空状态。
- 首次请求失败时展示错误和重试入口，不使用首页最近结果代替。
- 加载下一页失败时保留已加载数据，并允许再次触发加载。
- 切换筛选后的请求失败只影响当前筛选状态。

## 7. Referral

- Referral 使用当前用户快照中的 `referral_card`。
- 当 exchange、`user/info` 或 `user/update` 更新当前用户快照时，Referral 自动使用最新标题、说明、按钮文字、分享文案和链接。
- 标题、说明、按钮文字和分享链接均使用服务端字段。
- 配置缺失或必填字段异常时隐藏卡片；`share_text` 为可选字段，不控制卡片显隐。
- 点击后拉起系统分享面板，`share_text` 有效时分享文案和 `action_url`，否则仅分享 `action_url`。

## 8. 底部 Tab

- Home 与 Shop 是可选中的持久 Tab。
- 使用 `IndexedStack` 保留 Home 和 Shop 的页面状态。
- 中间 Scan 是操作入口，不作为持久选中页。
- 点击 Scan 进入 `TestFlowPage`，返回后保持此前选中的 Home 或 Shop。
- 支持通过 `HomePage.shopPath` 初始化到 Shop Tab。

## 9. 服务端交互

### 9.1 首页聚合数据

```http
GET /api/v1/app/index
Authorization: Bearer <access_token>
```

请求参数：无。

首页使用的成功响应字段：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "greeting": {
      "message": "Hello",
      "type": "morning"
    },
    "history": {
      "total": 10
    },
    "last_tests": [
      {
        "detection_type": "cortisol",
        "list": [
          {
            "id": 8,
            "date": "Aug 20",
            "time_period": "Morning",
            "detection_type": "cortisol",
            "value": "2–10",
            "unit": "ng/mL",
            "typical_range": "~2–10 ng/mL"
          }
        ]
      }
    ]
  }
}
```

完整响应、通用错误映射、鉴权和安全约束以试纸检测流程文档为准。

### 9.2 检测历史

```http
GET /api/v1/app/detections/history
Authorization: Bearer <access_token>
```

请求参数：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `detection_type` | string | 否 | `all`、`cortisol`、`testosterone`；默认 `all` |
| `end_date` | string | 否 | 分页截止日期；首次请求不传，后续使用 `next_end_date` |

当前约定的成功响应：

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "pagination": {
      "has_more": false,
      "next_end_date": "",
      "all": 5,
      "cortisol": 4,
      "testosterone": 1
    },
    "groups": [
      {
        "month_label": "August 2026",
        "sort_key": "2026-08",
        "items": [
          {
            "date": "Aug 4",
            "time_period": "Morning",
            "detection_type": "cortisol",
            "value": "2–10",
            "unit": "μg/dL",
            "typical_range": "~2–10 μg/dL"
          }
        ]
      }
    ]
  }
}
```

- 客户端以服务端实际返回的 `code` 进入成功或失败分支。
- 示例中的 `msg`、`reason` 和 `trace_id` 不作为首页业务分支依据，错误映射沿用通用网络层。
- `pagination.next_end_date` 在 `has_more=true` 时必须返回；`has_more=false` 时允许缺失或为空。

## 10. 状态与分层

### View

- 监听 `homeDashboardProvider` 和通知权限 Provider。
- 根据列表是否为空控制最近结果模块显隐。
- 派发 Profile、Scan、History、Referral 和 Tab 交互。
- 不直接发送网络请求或解析 JSON。

### Provider

- 组合当前用户和首页聚合接口数据。
- 将首页响应模型转换为 `HomeDashboardData`。
- 负责问候语、用户名和接口失败降级。

### Repository / Service

- 首页使用独立的首页 Repository 和 Service。
- Service 负责 `/api/v1/app/index` 请求和首页响应解码。
- 通用 `ApiClient` 负责鉴权、响应包解析和异常映射。

### 数据流

```text
HomeDashboard
  ↓ watch
homeDashboardProvider
  ├─ CurrentUserStorage
  └─ HomeRepository
       ↓
     HomeService
       ↓
     GET /api/v1/app/index
```

## 11. 当前模型

`HomeDashboardData` 包含：

- `greeting`：服务端问候语或客户端兜底。
- `userName`：完整用户名。
- `userInitial`：头像首字符。
- `totalTestCount`：来自首页接口 `history.total`。
- `cortisolResults`：Cortisol 最近结果。
- `testosteroneResults`：Testosterone 最近结果。
- `referralOffer`：当前静态 Referral 数据。

`HomeRecentResult` 包含：

- `type`
- `monthLabel`
- `dateLabel`
- `periodLabel`
- `valueLabel`
- `typicalRange`

## 13. 已确认规则

- 首页检测数据不使用写死测试数据。
- 首页通过 `/api/v1/app/index` 一次请求聚合数据，不传请求参数。
- `greeting.message` 用于首页问候语。
- 接口失败时问候语使用客户端兜底。
- `history.total` 用于首页检测总数。
- 外层 `last_tests[].detection_type` 决定结果模块类型。
- 某类型列表为空时隐藏对应模块。
- 最近结果保持服务端顺序并逐条展示，不限制客户端最大数量。
- 问候语下方展示完整用户名。
- Home 和 Shop 保持 Tab 状态，Scan 只作为流程入口。
- 每次进入 Home Tab 都重新请求首页检测结果。
- 首页不支持下拉刷新。
- 单条历史结果不支持进入详情页。
- 检测历史使用独立的 `/api/v1/app/detections/history` 接口。
- 历史筛选由服务端完成，切换筛选重新请求第一页。
- 历史列表使用 `next_end_date` 分页，并按 `sort_key` 合并相同月份。
- 历史筛选数量使用 `pagination.all/cortisol/testosterone` 服务端总数。

## 14. 完成标准

- 首页不再展示本地写死检测结果。
- 首页只发起一次聚合数据请求。
- 服务端问候语成功时正确展示。
- 服务端问候语不可用时展示客户端兜底。
- 接口失败时首页主体仍可操作。
- 无数据类型的最近结果模块正确隐藏；接口失败时隐藏全部最近结果模块。
- 检测入口进入现有试纸检测流程。
- 通知入口根据系统权限正确显示或隐藏。
- Widget 不直接请求接口或解析响应。
- 历史页可以按三种类型筛选，并正确重置分页状态。
- 历史分页按 `sort_key` 合并相同月份。
- 历史首次失败、空数据和加载更多失败使用不同状态处理。
